## 2. 核心原理

### 2.1 知识库使用三层模型

```
┌─────────────────────────────────────────┐
│  Layer 3: 深度阅读                   │
│  系统学习 → 逐篇精读 → 动手实践      │
├─────────────────────────────────────────┤
│  Layer 2: 快速定位                   │
│  关键词搜索 → 模块导航 → 关联跳转    │
├─────────────────────────────────────────┤
│  Layer 1: 认知入口                   │
│  README → 目录概览 → 学习路线        │
└─────────────────────────────────────────┘
```

**第一层：认知入口** — 了解知识库结构和学习路线
**第二层：快速定位** — 按需使用知识库解决具体问题
**第三层：深度阅读** — 系统学习某个专题或模块

### 2.2 检索优先级策略

遇到技术问题时，按以下顺序检索：

1. **精确术语检索**（如"ROP"、"Kerberoasting"）
2. **所属模块导航**（先在对应二级目录中找）
3. **相关模块交叉**（跨模块关联阅读）
4. **外部资源确认**（官方文档验证）

### 3.2 知识图谱使用

每篇文档底部的"知识关联"章节构成知识点之间的显式链接。使用知识图谱时：

- **正向追踪**：从解决的问题出发，追踪依赖的前置知识
- **反向追溯**：从技术栈顶层反查底层原理
- **交叉验证**：多个文档描述同一概念时，交叉核对一致性

### 3.3 知识库维护规范

**内容更新**：

- 发现技术决策更新时（如CVE修复方案变化），更新对应文档
- 新增实战经验时，补充到对应文档的"实战与示例"章节
- 技术过时的内容，在文档开头标注"已过时"并指向替代方案

**版本管理**：

```
status: 完成      # 内容完整、已验证
status: 待补充    # 内容基本完整，缺少部分示例
status: 待验证    # 部分技术细节未经环境验证
status: 待生成    # 仅创建了模板骨架
```

**一致性维护**：

- 术语统一（如统一使用"内网"而非"局域网"置换使用）
- 文件名与标题一致（kebab-case文件名 + H1标题）
- 前端标记统一（frontmatter字段规范）

### 3.4 个人笔记集成

个人笔记（type: personal）与AI生成笔记（type: ai-generated）的集成方式：

```
个人笔记                                AI笔记
├─ 背景与动机        关联到        ├─ 核心速查表
├─ 核心理解          关联到        ├─ 核心原理
├─ 实战记录          关联到        ├─ 实战与示例
├─ 待研究问题        关联到        ├─ 知识关联
└─ 参考来源          关联到        └─ 参考资料
```

个人笔记记录**个性化的理解与实践**，AI笔记提供**体系化的知识框架**，两者通过wikilinks关联。

### 4.2 高效学习工作流

```
1. 选择专题
   └─ 从知识体系全景或学习路线选择

2. 快速浏览
   └─ 阅读核心速查表和概述，建立认知

3. 深入阅读
   └─ 阅读原理和详细知识点，理解机制

4. 动手实践
   └─ 按实战示例搭建环境，运行代码

5. 关联扩展
   └─ 通过知识关联跳转到相关专题

6. 记录沉淀
   └─ 撰写个人笔记，补充个性化理解
```
