## 1. 概述

### 1.1 缺页中断的本质定义

缺页中断(Page Fault)是现代操作系统内存管理的基石机制。当进程访问某个虚拟地址时，内存管理单元(Memory Management Unit, MMU)在页表(Page Table)中查找对应的页表项(Page Table Entry, PTE)。如果发现该页表项标记为"不在内存中"（Present位为0），MMU便向CPU发出一个缺页异常(Page Fault Exception)，CPU暂停当前指令流，切换到内核态，跳转到预设的缺页中断处理程序入口（x86-64上为`do_page_fault`，ARM64上为`do_page_fault`）。

这一机制的核心意义在于：它允许操作系统在不将所有页面都加载到物理内存的前提下，为每个进程提供一个完整、连续的虚拟地址空间。进程看到的"内存"远大于实际物理内存，而缺页中断正是连接虚拟幻象与物理现实的桥梁。每一次缺页都是一次"按需供给"——只有真正被访问时，数据才从磁盘、交换空间或零页调入物理帧(Frame)。

### 1.2 知识体系定位

缺页中断处理处于操作系统三大核心子系统的交叉地带：它依赖[[虚拟内存原理：多级页表与地址翻译]]提供的页表结构，与[[MMU与TLB：加速机制与刷新时机]]的硬件加速机制紧密耦合，同时又深度参与[[内核内存管理：伙伴系统与slab分配器]]的物理页帧分配流程。

从安全视角看，缺页中断是用户态与内核态之间最频繁的隐式切换通道之一。一次典型的用户态程序运行可能触发数百万次缺页，每一次都经过内核的权限检查、页表修改和物理内存分配。这个高频路径既是操作系统性能的关键瓶颈，也是安全研究者关注的攻击面——缺页时序可以泄露进程的内存访问模式，堆风水(Heap Grooming)技术通过精心控制缺页行为来操纵内核内存布局。

### 1.3 核心应用场景

**按需分页(Demand Paging)**：进程启动时，内核只需建立虚拟地址映射，无需加载任何实际页面。当进程首次访问某页时触发缺页，内核从可执行文件或共享库中加载对应内容。这使得大型程序（如Chromium浏览器，启动时虚拟地址空间可达数GB）能在毫秒级完成"启动"。

**写时复制(Copy-on-Write, COW)**：`fork()`系统调用不复制父进程的物理页面，而是将父子进程的页表项都标记为只读。当任一方试图写入时触发COW缺页，内核才分配新的物理帧并复制内容。这使得`fork()`的时间复杂度从O(内存大小)降为O(页表大小)。

**内存映射文件(Memory-Mapped Files)**：`mmap()`将文件内容映射到进程地址空间。文件内容按需通过缺页加载，修改通过脏页写回机制同步到磁盘。数据库系统广泛利用此机制实现高效的随机I/O。

**交换(Swap)**：当物理内存紧张时，内核将不活跃页面写入交换空间(Swap Space)，释放物理帧。后续访问这些页面时触发缺页，内核从Swap读回数据。这使得系统能在物理内存不足时继续运行，但性能会显著下降。

**透明大页(Transparent Huge Pages, THP)**：Linux内核自动将连续的4KB页面合并为2MB或1GB的大页，减少TLB miss和页表层级。缺页处理中包含THP的拆分(Split)和合并(Merge)逻辑。

### 1.4 技术演进简史

1961年，Manchester大学的Atlas计算机首次实现了请求调页(Request Paging)机制，这是缺页中断的原型。1962年，Peter Denning在MIT的研究中形式化了工作集(Working Set)模型，为页面置换算法奠定了理论基础。

1970年代，UNIX系统引入了分页机制和简单的FIFO置换。1978年，Johnaco和Ricart提出了LRU的近似实现方案。1990年代，Linux内核从简单的时钟算法(Clock Algorithm)逐步演进到双链表近似LRU方案。

2000年代至今，Linux内核的页面回收(Page Reclaim)子系统经历了多次重大重构：2002年引入kswapd异步回收，2009年加入CGroup内存控制器的层级回收，2018年引入MGLRU(Multi-Gen LRU)以改善大规模工作集场景下的回收效率。2023年，MGLRU合并入Linux 6.1主线内核，成为现代Linux默认的页面回收策略。

## 2. 核心原理

### 2.1 缺页中断触发条件：四种情况

缺页中断并非只在"页面不在内存"时才触发。根据PTE的状态位组合，缺页可由以下四种情况引起：

**情况一：首次访问（Major缺页）**——进程访问一个虚拟页面，其PTE的Present位为0且没有任何有效的后备存储映射。内核需要从磁盘上的可执行文件、共享库或匿名页的Swap空间中读取数据到物理帧。这是最耗时的缺页类型，涉及磁盘I/O，延迟通常在毫秒级。

**情况二：写时复制（COW缺页）**——页面在物理内存中存在（Present=1），但PTE标记为只读（Write=1），且进程试图写入。内核判断这是COW场景，分配新物理帧，复制旧帧内容，更新PTE为可写。这种缺页不涉及磁盘I/O，延迟在微秒级。

**情况三：页被换出（Major缺页/Swap In）**——页面的PTE Present位为0，但PTE的交换条目(Swap Entry)字段记录了该页在交换空间中的位置。内核从Swap设备读取页面内容，分配物理帧，重建PTE映射。涉及磁盘I/O，延迟取决于Swap设备速度。

**情况四：非法访问（Segmentation Fault）**——进程访问的虚拟地址不在任何有效的VMA(Virtual Memory Area)映射范围内，或访问权限不匹配（如写入只读代码段、执行不可执行页面）。内核发送SIGSEGV信号终止进程。这类"缺页"实际上是内存保护机制的体现。

### 2.3 主缺页 vs 次缺页 vs 无效缺页

Linux内核在`/proc/meminfo`和`/proc/vmstat`中区分了三种缺页计数：

**主缺页(Major Fault)**：需要从磁盘读取页面的缺页，包括从可执行文件、共享库、mmap文件和Swap空间读入。由于涉及机械磁盘或SSD的I/O操作，延迟通常在0.1ms~10ms量级。内核在处理主缺页时会更新进程的`min_flt`和`maj_flt`计数器（通过`/proc/[pid]/stat`可查看）。

**次缺页(Minor Fault)**：不需要磁盘I/O的缺页，包括COW缺页、首次访问已映射但未加载的页面（如预读机制提前映射的页面）、以及页表项的权限修正。延迟通常在1~10微秒量级。大量次缺页累积也会对性能产生显著影响。

**无效缺页(Invalid Fault)**：访问的地址不在任何VMA范围内，或权限检查失败。这不是真正的"缺页"，而是内存访问违规。内核向进程发送SIGSEGV（段错误）或SIGBUS信号。

这三种缺页在安全分析中有不同含义：主缺页时序可用于推断进程的文件访问模式和内存使用量；次缺页在堆风水中可被利用来触发特定的内核分配行为；无效缺页则是缓冲区溢出检测和ASLR(Address Space Layout Randomization)绕过尝试的常见结果。

### 2.4 页面置换的需求：物理内存不足时的取舍

现代操作系统为每个进程提供远超物理内存的虚拟地址空间。一个64位进程理论上可寻址128TB内存，而典型服务器物理内存仅为64GB~1TB。当多个进程的活跃工作集(Working Set)总量超过物理内存容量时，操作系统必须做出抉择：哪些页面应该保留在内存中，哪些应该被换出(Swap Out)到磁盘？

页面置换算法(Page Replacement Algorithm)正是解决这一问题的决策引擎。其核心挑战在于：我们无法预知未来的内存访问模式，只能基于历史访问信息做出近似最优的选择。衡量一个置换算法的关键指标包括：

- **缺页率(Page Fault Rate)**：单位时间内的缺页次数，越低越好
- **抖动(Thrashing)**：系统频繁进行页面换入换出的状态，此时CPU大量时间花在I/O等待上而非有效计算
- **公平性**：避免某个进程被"饿死"（其页面被持续换出）
- **开销**：算法本身的CPU和内存开销不能过大

### 2.5 理想置换算法OPT与不可能实现的遗憾

最优置换算法(Optimal, OPT)由Belady于1966年提出：每次缺页时，选择在未来最长时间内不会被访问的页面换出。OPT能保证最低的缺页率，是所有置换算法的性能上限。

然而，OPT在实践中完全不可能实现——它需要预知未来的所有内存访问序列，这在冯·诺依曼架构下是不可计算的。OPT的价值在于提供一个理论基准(Benchmark)，用于评估其他算法的优劣。通过在离线回放(Replay)模式下比较实际算法与OPT的缺页率差距，研究人员可以量化算法的改进空间。

值得注意的是，OPT的不可实现性本身具有安全启示：它说明在动态系统中，任何基于局部性原理的启发式算法都存在被对手(Agent)通过精心构造的访问模式来"欺骗"的可能性，从而触发大量缺页，导致性能降级甚至内存耗尽——这正是缺页拒绝服务攻击(Page Fault DoS)的理论基础。

## 3. 详细知识点

### 3.1 FIFO置换：Belady异常与实现

先进先出(First-In, First-Out, FIFO)置换是最简单的页面置换算法：维护一个按页面进入内存时间排序的队列，每次需要换出页面时，选择队首（最早进入）的页面淘汰。

FIFO的优点是实现极简——只需要一个FIFO队列和一个指针。Linux 2.0之前的内核曾使用过FIFO的变体。但FIFO存在一个违反直觉的现象：Belady异常(Belady's Anomaly)，即增加物理帧数量反而可能导致缺页率上升。

```

Belady异常的根本原因在于FIFO不考虑页面的访问频率和最近使用时间。FIFO对所有页面一视同仁，无论它是被频繁访问的"热页"还是很久未使用的"冷页"。这一缺陷使得FIFO在实际操作系统中很少被直接采用。

### 3.2 LRU置换：精确实现的开销与近似算法

最近最少使用(Least Recently Used, LRU)置换算法基于时间局部性(Temporal Locality)原理：最近被访问过的页面在未来更可能再次被访问。LRU在每次缺页时选择最长时间未被访问的页面换出。

LRU在理论上接近OPT的性能，且不存在Belady异常。但精确实现LRU面临巨大的开销挑战：

**方案一：时间戳法**——每次页面访问时记录精确时间戳，置换时扫描所有页面选择时间戳最小者。问题：需要为每个PTE维护64位时间戳（8字节），且每次访问都需要一次内存写操作，TLB刷新后时间戳也需要更新。对于1GB物理内存（约256K个4KB页面），仅时间戳存储就需要2MB，且每次内存访问都增加一次额外写操作，这在硬件层面是不可接受的。

**方案二：计数器法**——维护一个全局计数器，每次内存访问时递增，每个页面记录最后一次访问时的计数器值。问题同上，且全局计数器存在溢出和并发竞争问题。

**方案三：栈法**——维护一个访问顺序栈，每次访问将对应页面移到栈顶，置换时选择栈底元素。问题：每次栈操作需要O(n)时间（n为页面数），且需要在多核间同步。

由于精确LRU的硬件实现代价过高，现代操作系统全部采用近似LRU(Approximate LRU)方案。Linux内核通过两种机制实现近似LRU：

**访问位(Accessed/Referenced Bit)**：x86-64架构的PTE中有一个Accessed位（位5），硬件在页面首次被访问时自动置1（不需要内核干预）。内核定期检查并清除这些位，来判断页面在过去一段时间内是否被访问过。

**二次机会(Second Chance)机制**：内核检查页面的Accessed位，如果为1则给"第二次机会"——将该位清除并跳过，继续检查下一个页面。如果为0则换出。这实质上是LRU的时间衰减近似：最近被访问过的页面更可能有置1的Accessed位。

### 3.3 Clock（二次机会）置换：NRU与Linux近似LRU

Linux内核的页面回收并不使用单一的Clock队列，而是采用Active/Inactive双链表结构来实现更精细的近似LRU：

**Active链表(Active List)**：存放最近被访问过的"年轻"页面。这些页面被认为在未来更可能被再次访问。当进程访问一个页面时，如果该页在Active链表中，内核将其移到链表尾部（"变年轻"）。

**Inactive链表(Inactive List)**：存放较长时间未被访问的"老化"页面。新页面首先进入Inactive链表头部。当Active链表过长时，链表头部的页面会被降级(Migrate)到Inactive链表头部。

**回收过程**：内核从Inactive链表头部开始扫描。如果页面的Accessed位为1，说明它在扫描间隔内被访问过，内核给它"第二次机会"——清除Accessed位，将其移到Active链表（如果仍然活跃）或Inactive链表尾部（如果访问频率不高）。如果Accessed位为0，则选择该页进行回收。

│ P_01 │ P_02 │ P_03 │ P_04 │ P_05 │
│ A=1  │ A=1  │ A=0  │ A=1  │ A=1  │

   │ 访问时移到尾部              │ 降级
   │ (变年轻)                    │ (老化)

┌──────┬──────┬──────┬──────┬──────┐

```

通过调整Active和Inactive链表的相对大小比例（通过`vm.vfs_cache_pressure`和`vm.swappiness`等参数控制），管理员可以针对不同工作负载优化页面回收行为。

### 3.4 Linux页面回收：kswapd、Direct Reclaim、Active/Inactive链表

Linux内核的页面回收(Page Reclaim)是一个多层次、多策略的复杂子系统。当系统物理内存不足时，有两种回收路径：

**kswapd——异步回收守护进程**：每个NUMA节点有一个kswapd内核线程。当空闲内存低于水位线(Watermark)的high值但尚未触及low值时，kswapd被唤醒开始后台回收。它扫描Active/Inactive链表，将页面写入Swap或丢弃干净页。kswapd的优势在于不阻塞用户进程，但它回收的速度可能跟不上高内存消耗应用的需求。

kswapd的水位线机制由三个阈值控制：
- `min`水位线：低于此值时，分配将被阻塞并触发直接回收
- `low`水位线：kswapd被唤醒开始后台回收
- `high`水位线：kswapd停止回收，系统回到正常状态

**Direct Reclaim——直接回收**：当分配请求到达但空闲内存已低于min水位线时，发起分配的进程被迫同步执行页面回收。这个进程会阻塞在`__alloc_pages_slowpath`中，直到回收到足够的空闲帧。Direct Reclaim是性能杀手——它不仅引入了I/O延迟，还可能导致调用者被写回(Swap Out)。

**内存压力的多级响应**：Linux内核的页面回收是一个渐进式降级过程。首先是kswapd后台回收，然后是Direct Reclaim同步回收，接着是OOM Killer杀死进程释放内存，最后在极端情况下触发内核Panic。理解这一降级链条对于性能调优和故障排查至关重要。

### 3.5 OOM Killer：内存耗尽的最终手段

当所有回收手段都无法满足内存分配请求时，Linux内核的OOM Killer(Out-of-Memory Killer)被触发，它会根据启发式评分选择并杀死一个或多个进程来释放内存。

OOM Killer的评分机制（基于`oom_badness`函数）主要考虑两个因素：
1. **进程的内存使用量**：使用内存越多的进程，得分越高（越可能被杀）
2. **进程的OOM分数调整值(oom_score_adj)**：通过`/proc/[pid]/oom_score_adj`可设置（范围-1000到1000），-1000表示绝对不杀，1000表示优先杀

OOM Killer被触发时，内核会打印详细的OOM报告到`dmesg`，包括每个进程的内存使用量、OOM分数、以及被选中进程的详细信息。关键系统进程（如systemd、sshd）的`oom_score_adj`通常被设置为负值以降低被杀概率。

安全视角：恶意用户可以通过大量分配内存触发OOM Killer，杀死关键系统服务（如数据库、安全监控进程），这是一种拒绝服务攻击手段。防御措施包括设置合理的`oom_score_adj`、使用CGroup限制内存使用、以及监控异常的内存增长。

### 3.6 Swap机制：交换空间与ZRAM压缩

Swap机制是物理内存不足时的缓冲区：将不活跃的页面写入磁盘上的交换分区(Swap Partition)或交换文件(Swap File)，释放物理帧供活跃进程使用。

**传统磁盘Swap**：数据写入磁盘，读写延迟受磁盘速度限制（HDD约5-10ms，SSD约0.1ms）。优点是容量可配置到很大，缺点是I/O延迟显著。

**ZRAM压缩Swap**：Linux内核的ZRAM驱动在内存中创建一个压缩的块设备。当系统需要Swap时，页面不写入磁盘，而是压缩后存储在ZRAM中。压缩比通常为2:1到3:1（取决于数据模式）。ZRAM的优势在于消除了磁盘I/O瓶颈，但会消耗额外的CPU周期进行压缩/解压缩。

ZRAM在嵌入式系统和Android设备上广泛使用。它通过`/sys/block/zram0/`下的sysfs接口配置，包括压缩算法（`comp_algorithm`，可选lz4、zstd、lzo等）和最大大小（`disksize`）。

`vm.swappiness`参数控制内核将匿名页(Anonymous Pages，即进程堆栈数据)换出到Swap vs 丢弃文件页(File Pages，如mmap映射的文件)的倾向。值范围0-200（Linux 5.8+），默认60。设为0时尽量不Swap，设为200时更积极地Swap。对于数据库服务器等I/O敏感场景，通常建议设为10-30。

### 3.7 安全视角：缺页时序侧信道、堆风水、页面置换对利用稳定性的影响

缺页中断处理在安全领域具有多重含义：

**缺页时序侧信道(Page Fault Timing Side-Channel)**：2019年，MIT的研究人员利用TLB侧信道与缺页中断时序，构建了跨虚拟机的信息泄露攻击。攻击者通过精心构造的内存访问模式触发缺页，观察缺页的响应时间来推断目标进程的内存布局和访问模式。在云计算环境中，这种攻击可以绕过传统的进程隔离机制。

**堆风水(Heap Grooming/Feng Shui)**：在利用内核漏洞时，攻击者需要控制内核堆的分配布局。通过触发特定的缺页中断，攻击者可以精确控制内核何时分配和释放物理页帧。例如，在利用内核UAF(Use-After-Free)漏洞时，攻击者可以在释放目标对象后立即触发大量COW缺页，迫使内核分配新的物理帧，这些新帧可能重用目标对象的内存空间，从而实现对已释放内存的重占(Reallocation)。

**页面置换对Exploit稳定性的影响**：在利用用户态漏洞时，如果攻击者的Exploit代码页面或堆数据被换出到Swap，重新访问时会触发Major缺页，这会引入不可预测的延迟并可能导致时序攻击(Timing Attack)失败。安全研究人员在构造Exploit时通常会：
1. 在触发漏洞前访问所有相关页面，确保它们在物理内存中
2. 通过`mlockall()`系统调用锁定进程的所有页面，防止被换出
3. 在虚拟机环境中禁用Swap或预留足够内存

**内存取证挑战**：页面置换导致内存取证(Memory Forensics)面临数据不完整性问题。当页面被Swap Out时，磁盘上的内存镜像可能只包含部分物理内存内容，Swap分区中的数据需要被正确关联到进程地址空间才能完整重建内存状态。Volatility等内存取证框架需要同时分析物理内存和Swap内容。

## 4. 实战与示例

### /proc/vmstat 缺页统计解读

`/proc/vmstat`是Linux内核导出的虚拟内存统计信息，其中包含详细的缺页计数器：

```bash
$ cat /proc/vmstat | grep -E "^(pgfault|pgmajfault|pgpgin|pgpgout|pswpin|pswpout|pgscan|pgsteal)"
pgfault 2847391       # 总缺页次数（major + minor）
pgmajfault 312        # 主缺页次数（需要磁盘I/O）
pgpgin 15847           # 从磁盘读入的页面数（KB）
pgpgout 23419          # 写出到磁盘的页面数（KB）
pswpin 287             # 从Swap读入的页面数
pswpout 1542           # 写入Swap的页面数
pgscan_kswapd 84721    # kswapd扫描的页面数
pgsteal_kswapd 82345   # kswapd回收的页面数
```

关键比值分析：`pgsteal/pgscan`是回收效率比，值接近1说明回收效率高（大部分扫描到的页面都是可回收的），值远小于1说明大量页面被扫描但无法回收（可能都在使用中）。`pswpout/pswpin`反映Swap的使用趋势——持续增长说明系统内存压力大。

### vmstat、sar 观察缺页行为

使用`vmstat`实时监控缺页行为：

```bash
$ vmstat 1 5
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----

 2  0  45024 128432  64128 2891264    8   24   120   384  4821 12543 35  8 55  2  0
 1  0  45024 127808  64128 2891264    0    0     0     0  3942 10234 28  5 67  0  0

```

`si`(Swap In)和`so`(Swap Out)列显示每秒的Swap I/O量。当`so`持续大于0且`free`内存持续下降时，说明系统正在经历内存压力。`wa`(I/O Wait)升高结合高`so`通常指示Swap thrashing。

使用`sar`进行历史趋势分析：

```bash
$ sar -B 1 5    # 页面统计
$ sar -W 1 5    # Swap活动
$ sar -r 1 5    # 内存使用率
```

### 用 madvise(MADV_SEQUENTIAL) 影响页面预取

`madvise()`系统调用允许进程向内核提供内存访问模式提示，影响页面预取(Page Prefetch)和回收决策：

```c
// 提示内核该区域将被顺序访问，内核会提前预取后续页面
madvise(addr, length, MADV_SEQUENTIAL);

// 提示内核该区域不太可能再被访问，内核可优先回收
madvise(addr, length, MADV_DONTNEED);

// 提示内核该区域会被随机访问，禁用预取
madvise(addr, length, MADV_RANDOM);

// 提示内核该区域会被频繁访问，保留在内存中
madvise(addr, length, MADV_WILLNEED);
```

`MADV_SEQUENTIAL`会触发内核的预读窗口(Readahead Window)扩大，提前将后续页面加载到物理内存。这对于文件扫描、数据库全表扫描等场景能显著减少缺页次数。`MADV_DONTNEED`会立即释放指定区域的物理页面，后续访问时会触发零填充缺页(Zero-Fill Fault)，返回全零页面。

### OOM日志分析与调优

OOM Killer触发时的关键日志特征：

```bash
$ dmesg | grep -i "oom\|out of memory\|killed process"
[12345.678901] Out of memory: Killed process 12345 (java) total-vm:8388608kB,
    anon-rss:4194304kB, file-rss:0kB, shmem-rss:0kB, UID:1000 pgtables:8192kB
```

日志中的关键字段：`total-vm`是进程的虚拟内存大小，`anon-rss`是驻留匿名内存大小（实际使用的物理内存），`pgtables`是页表占用。被杀进程通常是非关键但内存消耗最大的进程。

调优建议：
1. 对关键服务设置`oom_score_adj=-1000`或较低值
2. 使用CGroup的`memory.max`限制容器/服务的内存上限
3. 监控`/proc/meminfo`中的`MemAvailable`（而非`MemFree`）
4. 对于内存密集型应用，考虑调整`vm.overcommit_memory`为2（禁止过度提交）

## 5. 常见坑与避坑指南

### 5.1 缺页 ≠ 错误：major/minor缺页的区别

最常见的误解是将缺页与程序错误等同。实际上，绝大多数缺页是操作系统正常工作的一部分。一个新启动的进程在`main()`函数执行前，可能已经经历了数百次次缺页（加载C运行时库、设置TLS等）。只有Invalid类型的缺页（SIGSEGV/SIGBUS）才真正代表程序错误。

在性能分析中，关注maj_flt（主缺页）比关注总缺页数更有意义。高maj_flt率通常意味着内存不足导致频繁Swap，而高min_flt率可能只是进程在正常初始化。`/proc/[pid]/stat`的第10和12字段分别记录min_flt和maj_flt计数。

### 5.2 LRU时钟精度陷阱

近似LRU的精度取决于内核清除Accessed位的频率。如果扫描间隔太长，多个访问可能只被记录一次（粒度太粗）；如果太频繁，扫描本身的CPU开销会很大。

Linux内核通过`vm.vfs_cache_pressure`和MGLRU的多代(Multi-Generation)机制来平衡这一矛盾。MGLRU引入了多个年龄代(Generation)，每代有不同的扫描频率，对"年轻"页面扫描更频繁，对"年老"页面扫描更稀疏，从而在保持低开销的同时提高了近似精度。

### 5.3 Overcommit与OOM Killer的不可预测性

Linux默认的内存Overcommit策略(`vm.overcommit_memory=0`)允许内核承诺分配超过实际可用量的内存。这在大多数情况下工作良好（因为进程通常不会同时使用所有已分配的内存），但在极端情况下可能导致OOM Killer突然杀死关键进程。

使用`vm.overcommit_memory=2`（Strict Overcommit）可以禁止超过`CommitLimit`的分配。但这也可能导致合理的分配失败（如大型JVM需要预留但未立即使用的内存）。实践中更推荐使用CGroup的硬限制而非全局Overcommit策略。

### 5.4 Swap启用/禁用对安全工具的影响

在安全评估环境中，Swap的配置直接影响工具行为：
- **禁用Swap**：确保所有数据都在物理内存中，内存取证完整性更好，但内存不足时直接触发OOM
- **启用ZRAM Swap**：兼顾性能和容量，但压缩/解压缩的CPU开销可能影响timing侧信道测量
- **启用磁盘Swap**：性能影响最大，但为系统提供最大的内存弹性

对于渗透测试工具（如Metasploit、Burp Suite）运行的系统，建议至少保留2GB Swap以防OOM Kill关键工具。对于需要精确timing测量的场景（如Cache侧信道实验），应禁用Swap并使用`mlockall()`锁定内存。
