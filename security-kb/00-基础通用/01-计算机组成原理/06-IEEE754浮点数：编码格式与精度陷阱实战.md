## 1. 概述

浮点数是计算机表示**实数**的核心机制。IEEE 754 标准最早由 IEEE 于 1985 年发布（IEEE 754-1985），后经 2008、2019 两次修订，是目前几乎所有编程语言和硬件平台默认遵循的浮点算术规范。

浮点数的本质是一种**有理数的近似表示**——它用有限的二进制位编码一个指数和一个有效数字（尾数），从而在巨大的动态范围内以有限精度逼近实数。这带来两个根本性约束：

1. **精度有限**：单精度仅能精确表示约 7 位十进制有效数字，双精度约 16 位。超出精度范围的运算必然引入舍入误差。
2. **表示有洞**：在极大值附近，相邻浮点数的间距远大于 1，因此"相邻浮点数之差"可能远大于小数值本身，这是"大数吃小数"的根本原因。

从安全视角看，浮点行为的不确定性是多类漏洞的温床：协议解析中浮点字段的截断可导致整数溢出等价物；时间戳浮点比较可被侧信道利用；随机数生成器依赖浮点舍入模式可能产生偏差分布。理解 IEEE 754 编码布局和精度陷阱，是安全开发的基础素养。

## 2. 核心原理

### 2.1 科学计数法的二进制映射

IEEE 754 的设计思想源自科学计数法：将实数表示为

```
V = (-1)^S × M × 2^E
```

其中：
- **S** 为符号位（0 = 正，1 = 负）
- **M** 为有效数字（尾数），规格化时 1 ≤ M < 2
- **E** 为阶码（指数），经偏置（bias）编码后存储

### 2.2 指数偏置（Exponent Bias）

为避免指数域使用补码（增加比较电路复杂度），IEEE 754 对指数施加**固定偏置**：

| 格式 | 指数位宽 | 偏置值 | 实际指数范围 |
|------|---------|--------|-------------|
| 单精度 float | 8 位 | 127 | -126 ~ +127（规格化） |
| 双精度 double | 11 位 | 1023 | -1022 ~ +1023（规格化） |

存储时，指数域存储 `e = E + bias`。解码时，真实指数 `E = e - bias`。

### 2.3 隐含前导位（Hidden Bit）

规格化数的有效数字 M 在小数点前有一个隐含的 `1.`，因此 23 位尾数域实际提供了 24 位有效二进制精度（float）或 53 位（double）。这一设计不占存储空间，却将精度翻倍。

## 3. 详细知识点

### 3.1 编码布局

#### 单精度（32 位）

```
 31      30       23                0
┌───┬─────────┬──────────────────────────────┐
│ S │ Exponent│         Mantissa             │
│ 1 │  8 bits │          23 bits             │
└───┴─────────┴──────────────────────────────┘
  符号    指数       尾数（隐含前导 1.）
```

- **符号位 S**：第 31 位，0 = 正数，1 = 负数
- **指数域 Exponent**：第 30 ~ 23 位，8 位无符号整数，偏置 127
- **尾数域 Mantissa**：第 22 ~ 0 位，23 位小数部分，隐含前导 1

#### 双精度（64 位）

```
 63      62         52                  0
┌───┬───────────┬──────────────────────────────────────────┐
│ S │ Exponent  │              Mantissa                    │
│ 1 │  11 bits  │               52 bits                    │
└───┴───────────┴──────────────────────────────────────────┘
  符号    指数          尾数（隐含前导 1.）
```

- **符号位 S**：第 63 位
- **指数域**：第 62 ~ 52 位，11 位，偏置 1023
- **尾数域**：第 51 ~ 0 位，52 位

### 3.2 规格化数与非规格化数

#### 规格化数（Normalized）

当指数域 `e` 满足 `1 ≤ e ≤ 254`（float）或 `1 ≤ e ≤ 2046`（double）时，数为规格化数。有效数字 M = `1.fraction`（隐含前导 1）。

**示例**：将 -5.0 编码为单精度

```
-5.0 = -1 × 101.0₂ = -1 × 1.01 × 2²
  S = 1
  E = 2, e = 2 + 127 = 129 = 10000001₂
  fraction = .01000...₂ (23位)
  编码：1 10000001 01000000000000000000000
  十六进制：0xC0A00000
```

#### 非规格化数（Subnormal / Denormal）

当指数域 `e = 0` 时，数为非规格化数。此时有效数字 M = `0.fraction`（**隐含前导为 0**），且真实指数固定为 `E = 1 - bias`（即 -126 或 -1022）。

非规格化数的意义：
- 提供**渐进下溢**（gradual underflow），避免突然归零
- 使浮点运算满足**自反性**（x - x = 0 对所有有限数成立）
- 表示接近零的极小正/负数

**非规格化数最小正值**：
- float：`2^(-149)` ≈ 1.401298e-45
- double：`2^(-1074)` ≈ 4.940656e-324

#### 非规格化数对性能的影响

部分旧 CPU（如早期 Intel Pentium）在遇到非规格化数时触发**微码异常**（Denormal Assist），导致严重性能下降（数十倍甚至百倍）。现代 CPU 通常硬件处理非规格化数，但某些 SIMD 指令仍可通过 `DAZ/FTZ` 标志（MXCSR 寄存器）将非规格化数视为零以加速运算。这在安全场景中可能引入微妙的精度偏差。

### 3.3 特殊值

当指数域取极值时，浮点数表示特殊值：

| 条件 | 含义 | 指数域 | 尾数域 |
|------|------|--------|--------|
| `e = 0, fraction = 0` | **±0** | 全 0 | 全 0 |
| `e = 0, fraction ≠ 0` | **非规格化数** | 全 0 | 非零 |
| `1 ≤ e ≤ 254`（float） | **规格化数** | 正常 | 正常 |
| `e = 255, fraction = 0` | **±∞** | 全 1 | 全 0 |
| `e = 255, fraction ≠ 0` | **NaN** | 全 1 | 非零 |

#### ±0

- 有正零和负零之分，编码不同
- IEEE 754 规定：`+0 == -0` 为**真**
- 但 `1/+0 = +∞`，`1/-0 = -∞`，符号不同
- 安全注意：某些哈希函数或比较逻辑未正确处理 -0

#### ±∞

- 由溢出或 `1.0/0.0` 产生
- 有限数 + ∞ = ∞（符号一致）
- ∞ - ∞ = **NaN**（未定义）
- NaN ≠ NaN（IEEE 754 规定）

#### NaN（Not a Number）

NaN 分为两种：
- **Quiet NaN (qNaN)**：尾数最高位 = 1，沉默传播，不会触发异常。用于表示未定义运算结果。
- **Signaling NaN (sNaN)**：尾数最高位 = 0，会触发浮点异常处理器。常用于未初始化变量检测。

NaN 的位模式特征：
- 指数域全 1
- 尾数域非零
- 最高位 = 0 为 sNaN，= 1 为 qNaN

**NaN 比较规则**（IEEE 754-2019 §5.11）：
- `NaN != NaN` → **真**
- `NaN < x`、`NaN > x`、`NaN == x` → **假**
- `NaN` 可携带有效载荷（payload），用于调试

**安全影响**：NaN 的传播性在安全代码中可能导致异常状态静默传递，掩盖真实错误。某些语言运行时（如 V8）在 JSON 序列化时会丢弃 NaN 或将其转为 `null`，可能绕过校验。

### 3.4 指数偏置详解

偏置值的选取使得浮点数的**字节序排序**与**无符号整数排序**一致（正数情况），便于硬件快速比较。

**偏置计算**：
```
bias = 2^(k-1) - 1
```
其中 k 为指数位宽。

| 格式 | 指数位 k | 偏置 | 可表示的指数范围 |
|------|---------|------|-----------------|
| 半精度 float16 | 5 | 15 | -14 ~ +15 |
| 单精度 float | 8 | 127 | -126 ~ +127 |
| 双精度 double | 11 | 1023 | -1022 ~ +1023 |
| 扩展精度 x87 | 15 | 16383 | -16382 ~ +16383 |

### 3.5 舍入机制

IEEE 754 定义四种舍入模式，**默认为 Round to Nearest, Ties to Even**（RNE）：

| 模式 | 标志 | 行为 | 适用场景 |
|------|------|------|---------|
| **Round to Nearest, Ties to Even** | FE_TONEAREST | 四舍六入五成双 | 默认模式，通用计算 |
| Round toward Zero | FE_TOWARDZERO | 直接截断 | C `(int)` 强制转换语义 |
| Round toward +∞ | FE_UPWARD | 向正无穷方向取整 | 上界计算 |
| Round toward -∞ | FE_DOWNWARD | 向负无穷方向取整 | 下界计算 |

#### RNE 的"五成双"规则

当待舍入位恰好位于两个可表示浮点数正中间时，选择尾数最低位为 **偶数** 的那个。这是为了消除系统性偏差——传统"四舍五入"在统计上偏向 0.5 以上。

**示例**：`2.5` 在二进制中恰好位于 2 和 3 的正中间，RNE 选择 2（最低位 = 0，偶数）。

#### 截断（Round toward Zero）

C 语言中 `(float)int_val` 或 `(double)float_val` 的强制转换语义为截断，不四舍五入。这意味着 `int 2147483647` → `float` 时结果为 `2147483648.0f`（最近的可表示值），而非精确值。

### 3.6 精度丢失来源分类

精度丢失是浮点编程中最核心的陷阱，其来源可系统性分为五类：

#### 3.6.1 表示误差（Representation Error）

根本原因：**二进制无法精确表示大多数十进制小数**。

最经典的例子：`0.1` 在 IEEE 754 双精度中的实际值为：

```
0.1₀ = 0.0001100110011...₂（循环）
实际存储：0.1000000000000000055511151231257827021181583404541015625
```

类似地，`0.2`、`0.3` 都无法精确表示，因此 `0.1 + 0.2 != 0.3`。

#### 3.6.2 大数吃小数（Swamping / Cancellation）

当两个数量级相差悬殊的数相加时，较小的数可能落在较大数的精度范围之外，被"吞掉"。

**示例**：`1e20 + 1.0` 在双精度中结果仍为 `1e20`，因为 `1.0` 远小于 `1e20` 的 ULP（Unit in the Last Place）。

```
1e20 的 ULP = 1e20 / 2^52 ≈ 2.22e4
→ 1.0 被完全吞掉
```

#### 3.6.3 消去误差（Subtractive Cancellation）

两个**接近相等**的数相减时，有效数字大量消失，相对误差急剧放大。

**示例**：计算 `x² - y²` 与 `(x-y)(x+y)` 的差异。当 x ≈ y 时，前者产生严重消去误差。

#### 3.6.4 灾难性抵消（Catastrophic Cancellation）

消去误差的极端情况：当两个近似相等的数相减时，**所有有效数字都可能消失**，结果的相对误差无限放大。

**示例**：`1.0000001 - 1.0000000` = `0.0000001`，但原始精度仅剩 1-2 位有效数字。

#### 3.6.5 舍入累积（Rounding Accumulation）

长链运算中，每一步的舍入误差逐步累积。在循环迭代中尤其危险（如数值积分、矩阵乘法），误差可线性甚至超线性增长。

#### 3.6.6 整数到浮点转换丢失

32 位无符号整数 `0xFFFFFFFF`（4294967295）转换为 `float` 时，由于 float 仅 24 位有效精度，结果为 `4294967296.0f`（向上取整），产生 +1 的系统误差。

对于 64 位整数，转换为 `double` 时超过 53 位精度的位将被截断。

```c
    printf("=== 浮点比较陷阱 ===\n");

    double y = 0.3;
    printf("0.1 + 0.2 == 0.3 ? %s\n",
```

```bash
1.0/+0.0f = inf
1.0/-0.0f = -inf
NaN == NaN : false
NaN > 1.0  : false
NaN < 1.0  : false

=== 浮点比较陷阱 ===
0.1 + 0.2 == 0.3 ? false
fabs(x-y) < 1e-9 ? true
相对误差 < 1e-9 ? true

=== 舍入模式 ===
Round to nearest (ties to even):
  1.5 → 2 (偶数方向)
  2.5 → 2 (偶数方向)
Round toward zero:
  2.7 → 2
  -2.7 → -2

=== NaN 传播 ===
NaN + 1.0 = nan
NaN * 0.0 = nan
NaN - NaN = nan
任意含 NaN 的运算均产生 NaN
```

### 4.5 常见报错与现象速查表

| 现象 | 根因 | 解决方案 |
|------|------|---------|
| `0.1 + 0.2 != 0.3` | 0.1/0.2/0.3 均无法精确表示为二进制浮点 | 使用 `fabs(a-b) < eps` 比较 |
| 整数转 float 后 +1/-1 | float 仅 24 位精度，大整数被舍入 | 用 `double` 或 `long double` 中转 |
| `1e20 + 1.0 == 1e20` | 大数吃小数，1.0 小于 ULP | 调整计算顺序，先加小量 |
| `0.0 / 0.0 = NaN` | 未定义运算 | 检查分母后再除 |
| `1.0 / 0.0 = inf` | IEEE 754 定义 | 判断 inf 后特殊处理 |
| 函数返回 NaN | 输入域外或中间产生 NaN | 用 `math_errhandling` 检查 |
| -0.0 被误判 | `(-0.0 == 0.0)` 为 true | 用 `signbit()` 判断符号 |
| 非规格化数性能下降 | 旧 CPU 微码异常 | 启用 DAZ/FTZ 或避免极小值 |

## 5. 常见坑与避坑指南

### 坑 1：使用 `==` 比较浮点数

**问题**：由于表示误差，`0.1 + 0.2 == 0.3` 为假。

**避坑**：
```c
// 错误
if (a == b) { ... }

// 正确：绝对误差比较
#define EPSILON 1e-9
if (fabs(a - b) < EPSILON) { ... }

// 更稳健：相对误差比较
if (fabs(a - b) / fmax(fabs(a), fabs(b)) < EPSILON) { ... }

// 最稳健：C 标准库
#include <math.h>
if (isgreaterequal(fabs(a - b), EPSILON) == 0) { ... }
```

### 坑 2：大数吃小数

**问题**：`1e16 + 1.0` 结果仍为 `1e16`。

**避坑**：
```c
// 错误：按从大到小排序累加
double sum = 0;
for (int i = 0; i < 1000000; i++) {
    sum += data[i]; // 大量小值被大值吞噬
}

// 正确：Kahan 求和算法（补偿求和）
double sum = 0, comp = 0;
for (int i = 0; i < 1000000; i++) {
    double y = data[i] - comp;
    double t = sum + y;
    comp = (t - sum) - y;
    sum = t;
}
```

### 坑 3：整数→浮点精度丢失

**问题**：`uint32_t 0xFFFFFFFF` 转为 `float` 时产生 +1 误差。

**避坑**：
```c
// 错误
float f = (float)large_int; // 精度丢失

// 正确：使用 double 中转（53 位精度覆盖 32 位整数）
double d = (double)large_int; // 无损
float f = (float)d;           // 仍然可能丢失，需评估

// 对于 64 位整数，使用 long double 或直接比较原始整数
```

### 坑 4：NaN 静默传播

**问题**：NaN 在运算中静默传播，掩盖真实错误。

**避坑**：
```c
// 使用 math_errhandling（C99+）
#include <math.h>
#include <errno.h>

double result = sqrt(-1.0);
if (isnan(result)) {
    // 检查 errno 或使用 fetestexcept
    if (fetestexcept(FE_INVALID)) {
        fprintf(stderr, "FE_INVALID 异常\n");
    }
}

// 使用 fenv.h 显式检查异常
feclearexcept(FE_ALL_EXCEPT);
double r = some_operation();
if (fetestexcept(FE_OVERFLOW | FE_INVALID | FE_DIVBYZERO)) {
    // 发生异常，需处理
}
```

### 坑 5：-0.0 的隐秘行为

**问题**：`-0.0 == 0.0` 为 true，但 `1.0/-0.0 = -inf`。

**避坑**：
```c
// 检查符号位
#include <math.h>
if (signbit(x)) {
    // x 是负数或 -0.0
}
```

### 坑 6：编译器优化破坏浮点预期

**问题**：`-O2`/`-O3` 下编译器可能重排浮点运算、使用融合乘加（FMA），改变结果。

**避坑**：
```c
// 禁用特定运算的重排
#pragma STDC FP_CONTRACT OFF

// 或使用 volatile 强制内存访问
volatile double x = a * b + c; // 防止 FMA 融合

// GCC: -ffp-contract=off 禁用 FMA 融合
// GCC: -fno-fast-math 禁用所有激进浮点优化
```

### 坑 7：浮点侧信道泄漏

**问题**：浮点运算时间可能因输入不同（规格化 vs 非规格化）而变化，形成侧信道。

**安全建议**：
- 密码学运算**绝不使用浮点数**
- 时间敏感的安全比较使用**常数时间**实现
- 避免基于浮点结果做分支判断
- 在安全关键代码中禁用 DAZ/FTZ 以保持一致的时序行为
