## 2. 核心原理

### 2.1 无符号编码

无符号整数是最直观的编码方式：将一个非负整数直接转换为其等值的二进制表示。

对于 **n 位无符号整数**，其表示范围为：

```
0 ≤ x ≤ 2^n - 1
```

例如，8 位无符号整数（`uint8_t`）的范围是 **0 ~ 255**。

```
十进制    二进制（8位）
  0    →  0000 0000
  1    →  0000 0001
127    →  0111 1111
128    →  1000 0000
255    →  1111 1111
```

### 2.2 有符号编码：三种方案

有符号整数需要同时表示正数、负数和零。三种经典编码方案如下：

#### 2.2.1 原码（Sign-Magnitude）

**最高位为符号位**（0=正，1=负），其余位为绝对值的二进制。

```
十进制    二进制（8位原码）
 +0   →  0000 0000
 -0   →  1000 0000    ← 注意：有两个零！
 +5   →  0000 0101
 -5   →  1000 0101
+127  →  0111 1111
-127  →  1111 1111
```

**致命缺陷**：存在 **+0** 和 **-0** 两个编码，加法电路需要额外处理符号位，硬件实现复杂。范围不对称：-127 ~ +127（8 位）。

#### 2.2.2 反码（Ones' Complement）

符号位规则与原码相同，但**负数的数值位逐位取反**。

```
十进制    二进制（8位反码）
 +0   →  0000 0000
 -0   →  1111 1111    ← 仍然有两个零
 +5   →  0000 0101
 -5   →  1111 1010
```

**改进**：加减运算可以通过循环进位实现，比原码简单。但仍然有 +0 和 -0 的问题，范围仍为 -127 ~ +127（8 位）。

#### 2.2.3 补码（Two's Complement）——现代 CPU 的选择

**负数的补码 = 对应正数的反码 + 1**。

```
十进制    计算过程                        二进制（8位补码）
 +5   →  正数直接表示                    0000 0101
 -5   →  ~0000 0101 + 1 = 1111 1010 + 1 = 1111 1011
 +0   →                                0000 0000
  -0  →  不存在！                        N/A
+127  →                                0111 1111
-128  →  不存在对应正数                   1000 0000   ← 补码独占
-1   →  ~0000 0001 + 1 = 1111 1111      1111 1111
```

**核心优势**：
1. **唯一零**：+0 和 -0 的编码相同（`0000 0000`），消除了原码和反码的双零问题
2. **加减法统一**：硬件只需要一个加法器，`A - B = A + (-B)`，无需额外的减法电路
3. **范围对称性偏移**：n 位补码范围为 **-2^(n-1) ~ +2^(n-1)-1**，8 位为 **-128 ~ +127**，多表示一个负数
4. **按位运算统一**：`~x + 1 = -x`，取反加一即取相反数

### 2.3 为什么全行业选择了补码

| 特性 | 原码 | 反码 | 补码 |
|------|------|------|------|
| 零的唯一性 | ✗（+0, -0） | ✗（+0, -0） | ✓（唯一） |
| 硬件实现复杂度 | 高（需判断符号） | 中（循环进位） | **低（统一加法器）** |
| 加减法统一 | ✗ | 部分 | ✓ |
| 负数范围 | 对称 | 对称 | **多一个负数** |
| 现代 CPU 采用 | ✗ | ✗ | **✓（x86/ARM/RISC-V）** |

## 3. 详细知识点

### 3.1 补码的环形数学性质

补码的本质是一个**模 2^n 的整数环**。在模运算系统中，`a + (-a) = 0 (mod 2^n)`，这就是为什么 `-x = ~x + 1` 成立。

以 8 位补码为例，可以画出如下**补码环**：

```
            0  (0000 0000)
          / | \
    255  /   |   \  -1  (1111 1111)
  (1111 1110)|  (1111 1111)
        /    |    \
   128       |       127  (0111 1111)
  (1000 0000)|       |
        \    |      /
   -127  \   |   /  126
 (1000 0001) |  (0111 1110)
          \  |  /
          ...
```

更精确的环形表示（顺时针递增，8 位补码）：

```
                    0 (0x00)
                   / \
                 /     \
        -1 (0xFF)      1 (0x01)
              |            |
       -2 (0xFE)        2 (0x02)
              |            |
            ...          ...
              |            |
      -128 (0x80)    127 (0x7F)
                 \     /
                   \ /
              -127 (0x81) ... 126 (0x7E)
```

**关键性质**：

| 性质 | 表达式 | 示例（8位） |
|------|--------|-------------|
| 取相反数 | `-x = ~x + 1` | `-5 = ~5 + 1 = 0xFB` |
| 溢出环绕 | `127 + 1 = -128` | `0x7F + 0x01 = 0x80` |
| 减法变加法 | `a - b = a + (~b + 1)` | `3 - 5 = 3 + (-5) = 0xFE = -2` |
| 模运算等价 | `a + 2^n ≡ a (mod 2^n)` | `5 + 256 ≡ 5 (mod 256)` |

### 3.2 无符号与有符号的转换陷阱

C 语言标准规定，当有符号和无符号整数混合运算时，**有符号值会被隐式转换为无符号**（Usual Arithmetic Conversions）。这是一个极其危险的特性。

#### 3.2.1 隐式提升规则

```
signed int   +  unsigned int  →  unsigned int 运算
short        +  int           →  int 运算
int          +  long          →  long 运算
```

**核心规则**：如果两个操作数的类型不同，先进行**整数提升**（Integer Promotion），然后若一个为有符号一个为无符号，且无符号的秩 ≥ 有符号的秩，则有符号操作数被转换为无符号类型。

#### 3.2.2 经典陷阱：符号检查失效

```c
/* 运行环境：gcc 11.2, x86-64 Linux */
#include <stdio.h>
#include <string.h>

int main(void) {
    int user_input = -1;          /* 攻击者输入 */
    size_t buf_len = 1024;        /* 无符号类型 size_t */

    /* 看似安全的检查：user_input < buf_len ? */
    if (user_input < buf_len) {
        /* 
         * BUG: -1 被隐式转换为无符号！
         * (unsigned int)(-1) = 4294967295 = 0xFFFFFFFF
         * 4294967295 < 1024 ? → false
         * 所以此处不会执行 —— 表面看没问题
         */
        printf("Pass 1: size check passed\n");
    }

    /* 但如果比较方向反过来？ */
    if (user_input >= 0 && user_input < buf_len) {
        printf("Pass 2: safe with explicit check\n");
    }

    /* 
     * 危险场景：开发者以为 -1 会让 sizeof 返回负数截断
     */
    unsigned int len = (unsigned int)user_input;
    printf("len = %u (0x%X)\n", len, len);
    /* 输出: len = 4294967295 (0xFFFFFFFF) */

    /* 如果 len 用于 malloc —— 巨量内存分配，可能OOM崩溃 */
    /* 如果 len 经过截断变成小值 —— 缓冲区溢出 */

    return 0;
}
```

**运行输出**：

```
len = 4294967295 (0xFFFFFFFF)
```

#### 3.2.3 隐式转换完整对照表

| 场景 | 有符号值 | 转换后无符号值 | 安全影响 |
|------|----------|----------------|----------|
| `int` → `size_t` | `-1` | `SIZE_MAX` (4294967295 或 18446744073709551615) | 超大分配/绕过检查 |
| `int` → `size_t` | `-2` | `SIZE_MAX - 1` | 同上 |
| `int` → `size_t` | `-100` | `SIZE_MAX - 99` | 同上 |
| `short` → `unsigned short` | `-1` | `65535` | 16位场景同理 |
| `int` → `uint32_t` | `0x80000000` (有符号溢出) | `2147483648` | 范围误解 |

### 3.3 整数溢出：有符号 UB 与无符号环绕

#### 3.3.1 有符号整数溢出 = 未定义行为（UB）

C11 标准 6.5 §5 明确规定：**"If an exceptional condition occurs during the evaluation of an expression (that is, if the result is not mathematically defined or not in the range of representable values for its type), the behavior is undefined."**

这意味着编译器**可以任意处理**有符号溢出：

```c
/* 运行环境：gcc 11.2 -O2, x86-64 Linux */
#include <stdio.h>

int main(void) {
    int x = INT_MAX;  /* 2147483647 */
    int y = x + 1;    /* 有符号溢出 → UB! */

    /* GCC -O2 下，编译器可能：
     * 1. 直接删除包含溢出的分支（死代码消除）
     * 2. 假设溢出永远不会发生，优化掉检查
     * 3. 产生符合预期的环绕结果（-fwrapv）
     */
    if (y > x) {
        printf("y > x (unwrapped)\n");
    } else {
        printf("y <= x\n");
    }

    /* -O2 下此分支可能被编译器优化掉！ */
    if (x > 0 && x + 1 < 0) {
        printf("Overflow detected\n");  /* -O2 下可能永远不执行 */
    }

    return 0;
}
```

**不同编译器/优化级别的行为差异**：

| 编译选项 | 预期行为 | 说明 |
|----------|----------|------|
| `gcc -O0` | 溢出环绕（-2147483648） | 无优化，自然硬件行为 |
| `gcc -O2` | 编译器可能删除溢出检查分支 | 利用 UB 假设无溢出进行优化 |
| `gcc -fwrapv -O2` | 强制环绕 | `-fwrapv` 让有符号溢出变成定义行为 |
| `clang -O2` | 类似 GCC，可能更激进 | Clang 也会利用 UB 优化 |

#### 3.3.2 无符号整数溢出 = 定义行为（模运算环绕）

C11 标准明确规定：**无符号整数运算溢出是定义行为**，结果为模 2^n 运算。

```c
/* 运行环境：gcc 11.2, x86-64 Linux */
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint32_t a = 0xFFFFFFFF;  /* 4294967295 */
    uint32_t b = 1;

    uint32_t result = a + b;  /* 定义行为：环绕 */
    printf("0xFFFFFFFF + 1 = %u (0x%08X)\n", result, result);
    /* 输出: 4294967295 + 1 = 0 (0x00000000) */

    uint32_t c = 0;
    uint32_t d = c - 1;       /* 0 - 1 = 0xFFFFFFFF = 4294967295 */
    printf("0 - 1 = %u (0x%08X)\n", d, d);
    /* 输出: 0 - 1 = 4294967295 (0xFFFFFFFF) */

    return 0;
}
```

**输出**：

```
0xFFFFFFFF + 1 = 0 (0x00000000)
0 - 1 = 4294967295 (0xFFFFFFFF)
```

#### 3.3.3 溢出行为对比总结

| 属性 | 有符号整数 | 无符号整数 |
|------|-----------|-----------|
| 溢出定义 | **未定义行为（UB）** | **定义行为（模 2^n 环绕）** |
| 编译器优化风险 | 极高（可能删除溢出检查） | 无 |
| 可预测性 | 不可预测 | 可预测、确定性 |
| 安全编码建议 | **绝不可依赖溢出行为** | 可利用环绕特性但需谨慎 |

### 3.4 扩展与截断

#### 3.4.1 零扩展（Zero Extension）

将无符号整数从窄类型扩展到宽类型时，**高位全部填 0**。

```
uint8_t x = 0xFF;       →  uint16_t y = 0x00FF;
uint8_t x = 0xFF;       →  uint32_t z = 0x000000FF;
```

#### 3.4.2 符号扩展（Sign Extension）

将有符号整数从窄类型扩展到宽类型时，**高位复制符号位**。

```
int8_t x  = -5;  (0xFB)
→ int16_t y = 0xFFFB  (符号扩展：高位全填1)
→ int32_t z = 0xFFFFFFFB

int8_t x  = 127; (0x7F)
→ int16_t y = 0x007F  (符号扩展：高位全填0)
→ int32_t z = 0x0000007F
```

```c
/* 运行环境：gcc 11.2, x86-64 Linux */
#include <stdio.h>
#include <stdint.h>

int main(void) {
    int8_t  a = -5;
    int16_t b = a;     /* 符号扩展：0xFFFB */
    int32_t c = a;     /* 符号扩展：0xFFFFFFFB */

    printf("int8_t(-5)  = 0x%02X\n", (uint8_t)a);
    printf("int16_t(-5) = 0x%04X\n", (uint16_t)b);
    printf("int32_t(-5) = 0x%08X\n", (uint32_t)c);

    uint8_t  d = 0xFF;
    uint16_t e = d;    /* 零扩展：0x00FF */
    uint32_t f = d;    /* 零扩展：0x000000FF */

    printf("uint8_t(0xFF)  = 0x%02X\n", d);
    printf("uint16_t(0xFF) = 0x%04X\n", e);
    printf("uint32_t(0xFF) = 0x%08X\n", f);

    return 0;
}
```

**输出**：

```
int8_t(-5)  = 0xFB
int16_t(-5) = 0xFFFB
int32_t(-5) = 0xFFFFFFFB
uint8_t(0xFF)  = 0xFF
uint16_t(0xFF) = 0x00FF
uint32_t(0xFF) = 0x000000FF
```

#### 3.4.3 截断（Truncation）

将宽类型截断为窄类型时，**直接丢弃高位**，保留低 n 位。

```
int32_t x = 0x12345678;
int8_t  y = (int8_t)x;     /* y = 0x78 = 120 (仅保留低8位) */

int32_t a = -256;           /* 0xFFFFFF00 */
int8_t  b = (int8_t)a;     /* b = 0x00 = 0 (截断后符号位变0!) */

uint32_t c = 65536;         /* 0x00010000 */
uint8_t  d = (uint8_t)c;   /* d = 0x00 = 0 */
```

**截断的数学本质是取模**：`(uint8_t)x` 等价于 `x % 256`（对于无符号），对于有符号则是在模 256 的环中取值。

```c
/* 运行环境：gcc 11.2, x86-64 Linux */
#include <stdio.h>
#include <stdint.h>

int main(void) {
    int32_t big   = 0x1FFFFFF;   /* 536870911 */
    int8_t  small = (int8_t)big; /* 截断：0xFF = -1 */

    printf("int32_t(0x%08X) 截断为 int8_t → %d (0x%02X)\n",
           (uint32_t)big, small, (uint8_t)small);

    int32_t neg   = -256;          /* 0xFFFFFF00 */
    int8_t  pos   = (int8_t)neg;   /* 截断为 0x00 = 0! */
    printf("int32_t(-256) 截断为 int8_t → %d\n", pos);

    return 0;
}
```

**输出**：

```
int32_t(0x01FFFFFF) 截断为 int8_t → -1 (0xFF)
int32_t(-256) 截断为 int8_t → 0
```

### 3.5 整数溢出攻击经典模式

整数溢出在安全漏洞中的核心攻击路径：

```
用户输入（整数值）
    ↓
整数运算（乘法/加法溢出）
    ↓
产生"小"值（本应是大值）
    ↓
小值用于：
  (a) 内存分配 → 分配过小的缓冲区
  (b) 数组下标 → 越界读写
  (c) 循环边界 → 循环次数异常
  (d) 范围检查绕过 → 跳过安全校验
    ↓
堆/栈溢出 / 越界访问 → 代码执行
```

#### 3.5.1 缓冲区大小计算溢出 → 堆溢出

这是最经典的整数溢出漏洞模式：

```c
/* 运行环境：gcc 11.2, x86-64 Linux */
/*
 * 漏洞示例：整数溢出导致缓冲区过分配
 * 攻击者控制 count 和 elem_size
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void* vulnerable_alloc(int count, int elem_size) {
    /* 
     * BUG: count * elem_size 可能溢出！
     * 例如：count = 1073741824, elem_size = 4
     * 预期: 1073741824 * 4 = 4294967296 (需要 >4GB)
     * 实际: 1073741824 * 4 = 0 (32位溢出归零!)
     */
    int total = count * elem_size;  /* 整数溢出! */
    void *buf = malloc(total);      /* 分配 0 字节! */

    if (buf == NULL) {
        printf("malloc failed\n");
        return NULL;
    }

    printf("Requested: %d x %d = %d bytes\n",
           count, elem_size, total);
    printf("malloc returned: %p, actually allocated for 0 bytes\n",
           buf);

    return buf;
}

int main(void) {
    /* 攻击场景：构造触发溢出的输入 */
    void *buf = vulnerable_alloc(1073741824, 4);
    if (buf) {
        /* 
         * 后续代码如果向 buf 写入数据：
         * 如果 total 本应是 4GB，但 buf 只有 0 字节
         * → 堆溢出！
         * 这里我们用 memset 演示
         */
        printf("Writing to 0-byte buffer would cause heap overflow!\n");
        free(buf);
    }

    return 0;
}
```

#### 3.5.2 数组下标越界

```c
/* 运行环境：gcc 11.2, x86-64 Linux */
#include <stdio.h>
#include <stdint.h>

#define ARRAY_SIZE 100

int array[ARRAY_SIZE];

int get_element(int index) {
    /*
     * 安全检查：index 必须在 [0, ARRAY_SIZE) 范围内
     * 但如果 index 是负数，且 array 基地址 + 负偏移
     * 可以访问到数组之前或之后的内存
     */
    if (index >= 0 && index < ARRAY_SIZE) {
        return array[index];
    }
    return -1;
}

int main(void) {
    /* 
     * 场景1：负数下标绕过检查（如果缺少 >= 0 检查）
     */
    int bad_index = -10;
    printf("If check was 'index < ARRAY_SIZE' only:\n");
    printf("-10 < 100 → true → accesses array[-10]!\n");
    printf("Would read/write %zu bytes before array start\n",
           sizeof(int) * 10);

    /* 
     * 场景2：溢出后的小值
     */
    uint32_t huge = 0x80000000;  /* 2147483648 */
    int small_index = (int)huge; /* 截断为 -2147483648 */
    printf("\nuint32_t 0x80000000 → int %d\n", small_index);
    printf("If used as index → massive out-of-bounds!\n");

    return 0;
}
```

#### 3.5.3 CVE 案例分析

**案例 1：Linux Kernel `perf_swevent_init` 整数溢出（CVE-2010-4258 相关）**

内核 `perf_event_open` 系统调用在初始化软件事件时，`1ULL << file_config.type` 左移量未校验。当 `type` 值超过位宽时，左移产生未定义行为，导致内核内存越界访问。攻击者可从用户态触发内核 oops 或提权。

**案例 2：经典堆分配整数溢出（通用模式）**

在大量 CVE 中反复出现的经典模式——攻击者控制 `count` 和 `element_size`，使 `count * element_size` 溢出为一个小值，导致 `malloc` 分配过小的缓冲区，后续循环按原始大 `count` 写入数据，造成堆溢出。此模式在内核、Web 浏览器、多媒体解码器中均有大量案例。

**案例 3：有符号/无符号比较绕过（OpenSSH 2.x 风格）**

```
int auth_count;          /* 有符号 */
unsigned int max_tries;  /* 无符号 */

if (auth_count < max_tries) {
    /* 
     * 如果 auth_count 为负数（如 -1）：
     * 隐式转换为 unsigned: (unsigned)(-1) = 4294967295
     * 4294967295 < max_tries? → 永远 false
     * 
     * 如果 auth_count 为 -1 而比较方向相反：
     * max_tries > auth_count → max_tries > (unsigned)(-1)?
     * → 永远 false → 检查被绕过！
     */
    printf("Auth attempt allowed\n");
}
```

### 4.2 完整可编译示例：整数溢出漏洞模拟

```c
/* 运行环境：gcc 11.2 -std=c11 -O0, x86-64 Linux */
/*
 * 文件：integer_overflow_demo.c
 * 编译：gcc -std=c11 -O0 -o integer_overflow_demo integer_overflow_demo.c
 * 运行：./integer_overflow_demo
 *
 * 说明：演示整数溢出的三种典型场景及修复方法
 */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

/* ========== 场景1：缓冲区大小乘法溢出 ========== */
void demo_mul_overflow(void) {
    printf("===== 场景1：缓冲区大小乘法溢出 =====\n");

    int count = 1000000;
    int elem_size = 4000;
    int total = count * elem_size;  /* 溢出！ */

    printf("count = %d, elem_size = %d\n", count, elem_size);
    printf("(int)count * elem_size = %d\n", total);
    printf("(预期值: 4000000000, 实际溢出为: %d)\n\n", total);

    /* 安全修复：使用 size_t 并检查溢出 */
    size_t safe_total = (size_t)count * (size_t)elem_size;
    printf("修复后: (size_t)count * elem_size = %zu\n", safe_total);

    /* 更安全：使用 __builtin_mul_overflow (GCC/Clang) */
    int safe_count = count;
    int safe_elem = elem_size;
    int safe_result;
    if (__builtin_mul_overflow(safe_count, safe_elem, &safe_result)) {
        printf("__builtin_mul_overflow: 检测到溢出！安全中止。\n\n");
    }
}

/* ========== 场景2：有符号溢出 UB ========== */
void demo_signed_ub(void) {
    printf("===== 场景2：有符号溢出未定义行为 =====\n");

    int x = INT_MAX;
    printf("INT_MAX = %d\n", x);
    printf("INT_MAX + 1 = %d (硬件环绕结果)\n", x + 1);

    /* 这个检查在 -O2 下可能被编译器优化掉！ */
    int y = x + 1;
    if (y < x) {
        printf("检测到溢出：y < x\n");
    }

    /* 安全修复：运算前检查 */
    if (x > INT_MAX - 1) {
        printf("修复：运算前检查，避免溢出发生\n");
    }
    printf("\n");
}

/* ========== 场景3：有符号/无符号混合比较 ========== */
void demo_sign_unsigned_mix(void) {
    printf("===== 场景3：有符号/无符号混合比较 =====\n");

    int user_len = -1;
    size_t max_allowed = 1024;

    /* 危险比较 */
    if ((size_t)user_len < max_allowed) {
        printf("危险比较：通过！(user_len被转为 SIZE_MAX)\n");
    } else {
        printf("危险比较：拒绝 (通常的预期)\n");
    }

    /* 安全修复：显式检查符号 */
    if (user_len >= 0 && (size_t)user_len < max_allowed) {
        printf("安全比较：通过\n");
    } else {
        printf("安全比较：拒绝 (正确拒绝负数)\n");
    }
    printf("\n");
}

int main(void) {
    printf("整数溢出漏洞模拟演示\n");
    printf("========================\n\n");

    demo_mul_overflow();
    demo_signed_ub();
    demo_sign_unsigned_mix();

    printf("演示结束。\n");
    return 0;
}
```

**编译与运行**：

```bash
$ gcc -std=c11 -O0 -o integer_overflow_demo integer_overflow_demo.c
$ ./integer_overflow_demo
```

```

===== 场景2：有符号溢出未定义行为 =====
```

### 4.3 GCC 溢出检测内建函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `__builtin_add_overflow` | `bool __builtin_add_overflow(type1 a, type2 b, type3 *res)` | 加法溢出检测 |
| `__builtin_sub_overflow` | `bool __builtin_sub_overflow(type1 a, type2 b, type3 *res)` | 减法溢出检测 |
| `__builtin_mul_overflow` | `bool __builtin_mul_overflow(type1 a, type2 b, type3 *res)` | 乘法溢出检测 |

返回 `true` 表示溢出，安全结果写入 `*res`（即使溢出也会写入模运算结果）。Clang 同样支持这些内建函数。

|---------------|------|----------|

## 5. 常见坑与避坑指南

### 5.1 十大整数安全陷阱

| 编号 | 陷阱 | 危害等级 | 避坑方法 |
|------|------|----------|----------|
| 1 | 有符号溢出依赖环绕行为 | **致命** | 使用 `-fwrapv` 或运算前检查边界 |
| 2 | `size_t` 与 `int` 隐式转换 | **高** | 始终使用一致的无符号类型做大小计算 |
| 3 | `malloc(n * size)` 未检查乘法溢出 | **致命** | 使用 `__builtin_mul_overflow` 或 `safe_mul` |
| 4 | 有符号/无符号混合比较 | **高** | 统一类型，或显式检查符号 |
| 5 | 负数传入 `memcpy` 长度参数 | **致命** | `memcpy` 第三参数为 `size_t`，负数变巨大值 |
| 6 | 循环变量 `i--` 导致 `unsigned` 无限循环 | **中** | `unsigned` 从 0 递减会环绕到 `MAX` |
| 7 | 截断高位数据（如 `int` → `short`） | **中** | 使用 `stdint.h` 固定宽度类型 |
| 8 | `sizeof` 返回 `size_t` 与 `int` 比较 | **低** | 声明变量为 `size_t` |
| 9 | `~0` 的有符号行为 | **中** | `~0` 为 `-1`（有符号），`~0U` 为 `UINT_MAX` |
| 10 | 位移量 ≥ 类型位宽 | **致命/UB** | 移位前检查移位量 |

### 5.2 代码审查清单

安全代码审查时应关注以下模式：

```c
/* 危险模式1：乘法未检查 */
int total = count * size;
char *buf = malloc(total);

/* 安全修复 */
size_t total;
if (__builtin_mul_overflow(count, size, &total)) return -1;
char *buf = malloc(total);

/* 危险模式2：减法产生负数用于大小 */
int remain = total - consumed;
memcpy(dst, src, remain);  /* remain 可能为负 → SIZE_MAX! */

/* 安全修复 */
if (total < consumed) return -1;
size_t remain = (size_t)(total - consumed);
memcpy(dst, src, remain);

/* 危险模式3：有符号循环边界 */
for (int i = start; i < end; i++) {
    /* 如果 start > end，循环可能永远不执行
       或如果 end 来自无符号比较，可能被绕过 */
}

/* 安全修复：统一用 size_t 且做前置校验 */
if (start > end) return -1;
for (size_t i = start; i < end; i++) { ... }
```

### 5.3 安全编码实践清单

1. **使用固定宽度类型**：`int32_t`、`uint64_t` 替代 `int`、`long`，消除平台差异
2. **统一使用无符号做大小计算**：`size_t`、`uint32_t`，避免符号扩展问题
3. **运算前检查边界**：乘法前检查 `a > SIZE_MAX / b`
4. **启用编译器保护**：`-ftrapv`（有符号溢出陷阱）、`-fsanitize=signed-integer-overflow`
5. **使用安全算术库/内建函数**：GCC `__builtin_mul_overflow`、SafeInt（C++）、Rust checked arithmetic
6. **有符号/无符号不混用**：如果必须混用，先做显式类型转换并检查符号
7. **输入验证**：在整数运算之前验证所有外部输入值的范围合理性
8. **审计 malloc 参数**：`malloc` 的所有参数表达式必须经过溢出检查
9. **考虑用更安全的语言**：Rust、Go 等语言在编译期或运行时自动检测整数溢出
10. **启用 AddressSanitizer**：`-fsanitize=address` 可在运行时捕获整数溢出导致的堆越界
