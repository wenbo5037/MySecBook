## 1. 概述

计算机硬件体系是一座「分层抽象」的大厦。自底向上看，它从物理世界最基本的粒子运动（电荷）出发，逐步抽象出逻辑门、组合逻辑电路、时序逻辑电路、可编程处理器、再到今天复杂的多核SoC。理解这条自底向上的「抽象阶梯」，是安全从业者区别于普通使用者的分水岭：逆向工程师在分析一个二进制样本时，本质上是在「逆着」这条阶梯向下追溯；而漏洞利用的终点，往往是寄存器、栈、页表这些最接近硬件的概念。

### 1.1 技术定义与本质

**计算机硬件体系的本质**：用**受控的电压高低（逻辑0/1）** 驱动晶体管开关，通过**逻辑门的组合**构造能完成算术与逻辑运算的电路，再通过**时序电路**存储状态、控制执行节奏，最终构建出能「自主执行一整套指令」的中央处理器及其附属系统。

这里有一个关键的心智模型：**所有计算，本质上都是电压的开关与搬运。** 我们在代码里看到的整数加法 `a + b`，最终被翻译成一条 `ADD` 指令，在硬件上则是若干晶体管瞬间完成的开合动作。C语言的 `int`、Python 的整数对象，都是更上层语言的抽象；硬件的世界里只有比特（bit）与逻辑门。

### 1.2 知识体系定位

在整条安全知识链中，本主题是所有底层难度问题的「地基」：

- **逆向工程**：反汇编出来的 `mov eax, [ebp-4]` 需要理解寄存器、栈、内存总线。
- **二进制漏洞**：栈溢出与返回地址覆盖依赖对栈帧布局和 `call`/`ret` 指令的理解。
- **Fuzzing与性能**：覆盖率引导工具需要理解硬件分支与缓存行为。
- **内核安全**：Ring0/Ring3 特权级、页表、TLB 全部是硬件提供的或协作的机制。

### 1.3 核心应用场景

1. **CPU 工作原理讲解与面试准备**：理解流水线、乱序执行、分支预测是系统方向面试的必考内容。
2. **本地实验**：用模拟器（如 Logisim）从零搭建一个 8 位 CPU，亲手验证「从逻辑门到CPU」的可行性。
3. **安全逆向**：识别指令集与微架构差异，评估漏洞利用的稳定性（如侧信道）。
4. **性能工程**：缓存友好的代码、SIMD 向量化、分支优化都根植于底层硬件模型。

## 2. 核心原理

### 2.1 抽象阶梯：从晶体管到CPU

很多初学者会跳过这一层，直接进入汇编与寄存器。但「从逻辑门到CPU」的核心原理，恰恰是这条**抽象阶梯**。我们把它严格拆解为五层：

```
                    第5层: 指令集架构 ISA   (抽象: 程序员/编译器所见)
                           ↕ 微架构实现 (乱序执行、超标量...)
                    第4层: 处理器的控制与数据通路 (取指/译码/执行/访存/写回)
                           ↕ 状态寄存器、组合逻辑、多路选择器
                    第3层: 时序逻辑电路 (寄存器、计数器、触发器) 
                           ↕ 时钟信号驱动
                    第2层: 组合逻辑电路 (加法器、译码器、多路选择器)
                           ↕ 布尔代数
                    第1层: 逻辑门 (AND/OR/NOT/NAND...) 
                           ↕ 电学实现
                    第0层: 晶体管作为电控开关 (MOSFET) ↙ 电压高低 = 逻辑0/1
```

这一垂直分层，正是本章节最想让你建立的心智模型。Security 语境里，**每一层都可能引入新的攻击面**：逻辑层可以出现侧信道（如功耗分析），微架构层有 Spectre/Meltdown，指令层有未文档化的指令，总线层有 DMA 攻击。

### 2.2 核心架构：冯·诺依曼体系结构

现代计算机绝大多数遵循 **冯·诺依曼体系结构**（存储程序原理）：

1. **存储程序**：指令与数据以相同方式存储在同一个存储器中。
2. **五大部件**：运算器（ALU）、控制器（CU）、存储器（Memory）、输入设备、输出设备。
3. **指令周期**：取指（Fetch）→ 译码（Decode）→ 执行（Execute）→ 访存（Memory）→ 写回（Write Back），循环往复。

与之对照的是**哈佛结构**（指令与数据存储分离，常见于嵌入式芯片如ARM Cortex-M、DSP），以及现代处理器内部的**改进型哈佛结构**（L1指令缓存与L1数据缓存分离）。

```
冯·诺依曼体系结构示意图

        ┌──────────────────────────────────────────────────┐
        │                  主存储器 (Main Memory)           │
        │   [指令] [数据] [指令] [数据] ...同一地址空间       │
        └───────────────┬────────────────┬─────────────────┘
                        │ 地址总线AB     │ 数据总线DB
                        ▼                ▼
        ┌──────────────────────────────────────────────────┐
        │              中央处理器 (CPU)                      │
        │  ┌──────────┐   ┌──────────┐   ┌──────────┐      │
        │  │  控制器CU │◄─►│  运算器ALU│   │  寄存器组 │      │
        │  │  (译码/   │   │ (算术/    │◄─►│ (通用/     │      │
        │  │   时序)   │   │  逻辑运算) │   │  专项)     │      │
        │  └──────────┘   └──────────┘   └──────────┘      │
        └───────────────┬───────────────────┬──────────────┘
                        │ 控制总线CB        │
                        ▼                   ▼
                 ┌─────────┐          ┌─────────┐
                 │  输入设备 │          │  输出设备 │
                 └─────────┘          └─────────┘
```

### 2.3 CPU核心组成

- **运算器（ALU）**：执行加法、减法、按位与/或/异或、移位等操作。加法运算本身可以由 HA（半加器）/FA（全加器）串联成加法器完成，详见后续知识点。
- **控制器（CU）**：从取指开始，解释指令、生成控制信号（读/写/选择器使能等），指挥数据通路完成操作。
- **寄存器堆（Register File）**：CPU内部的高速存储，如传统x86的 EAX/EBX… 或 ARM 的 R0-R15。寄存器是CPU与内存之间的桥梁。
- **时钟发生器**：产生周期性时钟信号，同步所有时序逻辑。

### 2.4 现代CPU内部进阶结构（微架构视角）

现代CPU（如Intel Core、AMD Zen、ARM Cortex-A系列）在ISA之上叠加了复杂的微架构：

- **流水线**：将指令周期拆成多个阶段，多条指令重叠执行，吞吐率大幅提升（如14-20级超深流水线）。
- **超标量（Superscalar）与乱序执行（OoO）**：一个周期发射多条指令，通过保留站（Reservation Station）、重排序缓冲（ROB）打乱指令顺序执行，再按原序提交结果。
- **分支预测**：使用BTB（分支目标缓冲）与各种预测器猜测分支方向，预测错误时回滚（流水线冲刷）。
- **缓存层次**：L1/L2/L3 Cache。L1通常分开指令与数据，延迟几纳秒；主存延迟几十到上百纳秒。缓存的引入深刻影响性能，也成为侧信道攻击的核心战场。

这些内容会在后续笔记中逐篇展开，这里只需要建立「ISA是契约，微架构是实现」的认知。

## 3. 详细知识点

### 3.1 逻辑门：一切计算的细胞

逻辑门是最基础的计算单元，通过布尔代数表达。核心逻辑门包括：

| 逻辑门 | 符号 | 布尔表达式 | 真值特点 |
|--------|------|------------|----------|
| NOT | ! | ¬A | 反相器，输出取反 |
| AND | & | A·B | 全部为1才为1 |
| OR | \| | A+B | 任一为1即为1 |
| NAND | ~& | ¬(A·B) | 与非门，**通用门** |
| NOR | ~\| | ¬(A+B) | 或非门，**通用门** |
| XOR | ^ | A⊕B | 不同则为1（半加法核心） |

**重要事实**：NAND门和NOR门是**通用门**，单靠其中一种就能构造所有其他逻辑门。这在芯片设计上意义重大：制造工艺上，避免某些门的晶体管组合，或降低延迟，可以用同一种门统一构建标准单元库。

```
用两个NAND门构造AND门(标准方法), 用NAND构造NOT:

  A ──┬─[NAND]── X          NAND:  A B ──► Y = ¬(A·B)      
      │         │
  B ──┴─        │
                ├─[NAND]──► AND输出 = A·B
  X ────────────┘

  NOT只需将NAND的两个输入接在一起：
  A ─┬─[NAND]─► ¬A
     └───────┘
```

### 3.2 组合逻辑：加法器与ALU

组合逻辑的输出**只取决于当前输入**（无记忆）。典型代表：加法器、译码器、多路选择器。

**半加器（Half Adder, HA）**：计算两个1位数之和，输出`和S`与`进位C`。
```
S = A ⊕ B        （异或）
C = A · B        （与）
```

**全加器（Full Adder, FA）**：考虑来自低位的进位`Cin`。
```
S  = A ⊕ B ⊕ Cin
Cout = (A·B) + (Cin·(A⊕B))
```

**行波进位加法器（Ripple-Carry Adder, RCA）**：将N个全加器串联，低位进位送到高位。缺点是每级进位要依次「波」过去，延迟随位宽线性增长。与之相对的是**超前进位加法器（CLA, Carry-Lookahead）**，通过生成项G与传播项P并行计算进位，显著降低延迟，是快速除法/乘法单元的基础。

### 3.3 时序逻辑：寄存器与状态

时序逻辑的输出**依赖于历史状态**（有记忆），由时钟驱动。核心单元：

- **D触发器（D Flip-Flop）**：在每个时钟上升沿，将D输入锁存到输出Q。单个D触发器就是一个1位存储单元。
- **寄存器**：由一组D触发器构成，同步保存一个多位数据，是CPU内部的「微型内存」。
- **锁存器（Latch）**：对时钟电平敏感而不是沿敏感，现代同步设计尽量避免使用以降低时序风险。

时序电路还有更复杂形态：计数器（程序计数器PC的基础）、移位寄存器（乘除法、CRC），以及状态机（FSM）——控制器的核心。

### 3.4 控制与数据通路：如何执行一条指令

假设我们有一个最简8位CPU，指令 `LDA #05H`（把立即数5装入累加器）。执行过程：

```
1. 取指:   PC指向内存地址 → 发出读请求 → 读出二进制指令字节
           -> 同时PC自增 (PC <- PC+1), 为下一条做准备
2. 译码:   控制器识别操作码段(如 0x3E 表示LDA立即数)
3. 执行:   控制信号打开"立即数→累加器"的数据通路
4. 写回:   累加器A = 5, 状态标志更新(NF/ZF等)
```

控制器的本质是一个**有限状态机**，时钟的每个节拍推进一个状态，生成一组控制信号（读内存、写寄存器、选择ALU操作数等）。

### 3.5 存储器层次结构：速度与容量的妥协

存储器层次（Memory Hierarchy）是现代计算机性能的关键：

| 层级 | 典型容量 | 典型延迟 | 说明 |
|------|----------|----------|------|
| 寄存器 | ~百字节 | <1ns | CPU内部，指令直接寻址 |
| L1 Cache | 32-64KB | ~1ns | 指令/数据分离 |
| L2 Cache | 0.5-2MB | ~3-10ns | 每核私有 |
| L3 Cache | 8-64MB | ~15-40ns | 多核共享 |
| DRAM 主存 | 8-128GB | ~60-120ns | 按行/列寻址，需要刷新 |
| SSD / HDD | 数百GB-数TB | 数十us~数ms | 非易失 |

### 3.6 指令集与微架构的关系

- **指令集架构（ISA）**：程序员/编译器可见的「契约」，如 x86-64、ARMv8-A、RISC-V。它规定寄存器集、指令语义、寻址模式、异常模型。
- **微架构（Microarchitecture）**：ISA 的实现细节，如流水线深度、射宽（issue width）、缓存大小、乱序执行窗口。

同一ISA可以有多种微架构；这正是「程序兼容、性能各异」的原因。攻击者关注的侧信道漏洞（如Spectre变体），本质上是微架构实现（推测执行、缓存）与ISA约定（顺序隔离）之间的不匹配。

## 5. 常见坑与避坑指南

### 5.1 把「软件抽象」当成「硬件模型」

- C语言中的 `int i;` 并不意味着硬件存在「整型变量」单元；硬件上只有寄存器与内存地址。Stack变量其实在物理上是内存与缓存的映射。
- 调试时若脑内模型是「堆栈帧像结构体一样存在」，建议把它还原成「地址与寄存器」视角。

### 5.2 混淆 ISA 与微架构

- 问「这条指令要几个时钟周期？」——**在乱序执行的现代CPU上，这个答案本身是动态的**，取决于数据依赖、缓存命中率、分支预测是否正确。
- x86的 `add` 可能在1个周期内完成，也可能被拆解为多个微指令 `uops`，延迟因代际而异。

### 5.3 把「主频」等同于性能

- `3.5GHz` 的 Core i9 与 `4.0GHz` 的老赛扬明显不是同一档性能。IPC（每周期指令数）、缓存、内存带宽、指令集扩展共同决定性能。
- **评测观点**：本笔记所述主频竞赛结束的事实，印证性能评价请一律以实测Benchmark为准，而不是只看主频。

### 5.4 忽略字节序与位宽

- 调试硬件相关代码时，大小端（Little/Big Endian）是常见bug来源，尤其是在涉及网络协议、跨平台二进制解析时。详情见 [[字节序：大小端判定与网络字节序转换]]。

### 5.5 忘记同步问题

- 多核处理器上的 `++i` 不是原子操作；从硬件视角，它包含「读→改→写」三步，可能被其他核心打断。这为竞态漏洞与利用提供了土壤。

### 5.6 过渡依赖「教科书图表」

- 很多教科书把CPU画成固定方块，但现代CPU内部是若干「小核心」与共享资源交织。如L3是分片（slices）结构，每片有独立控制器，这不是简单的单一缓存。
