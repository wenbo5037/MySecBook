# 01-001 二进制安全概览与学习路线

## 基础信息
- 难度：入门
- 前置知识：无
- 对应语言等级：熟悉级

## 核心原理
二进制安全研究的是程序在编译为机器码之后的内部行为，研究对象是 PE（Windows）、ELF（Linux）、Mach-O（macOS）等二进制文件格式。与源码安全（如 Web 应用代码审计）不同，二进制安全关注编译器产物，即指令流、数据布局、调用约定与内存布局，因此常见的攻击面包括栈溢出、堆越界、Use-After-Free、类型混淆与逻辑漏洞。其方法论核心是「从字节还原意图」：在没有源码或仅需确认漏洞在实际产物中的可触发性时，通过逆向与动态分析建立程序模型。

权威依据：Intel Software Developer's Manual（SDM）描述了 x86-64 指令集与调用约定；System V AMD64 ABI 定义了 C 与汇编跨层交互的内存布局规则。

## 技术要点
- 二进制类型：PE/ELF/Mach-O 各自的节（section）与段（segment）、入口点与导入表。
- 汇编基础：x86/x86-64 通用寄存器、栈帧结构（rbp/rsp、返回地址位置）、常用指令（mov、lea、call/ret、jmp）。
- 逆向工具链：静态分析（Ghidra、IDA Pro）、动态调试（GDB、WinDbg、x64dbg）、二进制解析（radare2、file、readelf、objdump）。
- 防护机制：NX（不可执行栈）、ASLR、Stack Canary、RELRO、PIE、Control-flow Integrity（CFI）。
- 学习主线：反汇编识读 → 栈与堆内存模型 → 漏洞模式（栈溢出/堆利用）→ 利用技巧（ROP、ret2libc）→ 防护绕过 → Fuzzing 自动化。

## 实践示例
环境：Ubuntu 22.04 LTS（x86_64）、GCC 11.4、GDB 12.1、readelf 2.38、Ghidra 11.1。

对任意程序查看目标文件头与节信息：
```bash
file ./vuln
readelf -h ./vuln
readelf -l ./vuln
gdb -q ./vuln
```
`readelf -h` 输出 ELF header，其中 `Type`（EXEC/DYN 反映是否 PIE）、`Machine`、`Entry point address` 为最重要的定位信息。

## 常见问题与误区
- 误区一：认为「会编译就能做二进制安全」。实际上还需理解 ABI 级别的调用约定与内存布局，编译视角与逆向视角存在明显差异。
- 误区二：混淆「段（segment）」与「节（section）」。程序加载关注 segment（由程序头 Program Header 描述），链接与符号查找关注 section（由节头 Section Header 描述）。
- 误区三：忽略 ASLR/PIE 的存在。未关闭防护的现代系统上，固定地址的 shellcode 与 ret2text 通常无法直接使用，必须先处理重定位。
- 注意：仅可在本人或经授权授权的测试环境（如本地编译的漏洞程序、CTF 题目、靶场）中练习。
