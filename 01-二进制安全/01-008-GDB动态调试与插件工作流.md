# 01-008 GDB 动态调试与插件工作流

## 基础信息
- 难度：中级
- 前置知识：[[01-002-x86-64汇编与栈帧基础]]、[[01-003-ELF文件格式与链接机制]]
- 对应语言等级：精通级

## 核心原理

GDB（GNU Debugger）通过 Linux 的 **ptrace** 系统调用控制被调试进程的内存、寄存器与执行流：`PTRACE_TRACEME` 建立被追踪关系，`PTRACE_CONT`/`PTRACE_SINGLESTEP` 控制运行，`PTRACE_PEEKDATA`/`PTRACE_POKEDATA` 读写内存，`PTRACE_SYSCALL` 在每次系统调用处停下。软件断点的机制是 GDB 把目标地址处首个字节临时改写为单字节 `int3`（0xCC），命中后再恢复原字节并回退 EIP/RIP 以实现重现断点命中。硬件断点则借助调试寄存器 DR0-DR3（x86/64 架构 4 个可用），不修改代码，适合只读代码段与条件断点。watchpoint（数据断点）多数由硬件 DR 寄存器实现（受数量限制），软实现时退化为单步比对，速度慢。

数据断点在利用开发中极常用：在缓冲区与返回地址之间设 watchpoint，就能精确定位溢出何时触及关键位置。另一方面，GDB 默认对**每次启动的进程禁用 ASLR**（`set disable-randomization on`），这使得现场调试地址固定、便于计算，但也意味着调试态与真实运行态的地址不同——通过开启 idea 前务必清楚。

## 技术要点

### 启动与附加
- `gdb ./prog` 本地调试；`gdb ./prog core` 分析 core dump（`ulimit -c unlimited` 后崩溃生成）。
- `gdb -p <pid>` 附加运行中进程（受 ptrace 权限约束）。
- 远程：`gdbserver :12345 ./vuln` + 本地 `target remote :12345`；配合 qemu-user 可跨架构调试。

### 断点与观察
- `break *0x401234`、`break main`、`break *(main+12)`；`tbreak` 一次性断点，`rbreak regex` 正则。
- 条件断点：`break *addr if rax == 5`。
- watchpoint：`watch $rsp-32`（硬件数据断点）、`rwatch` 读断点、`awatch` 读写断点。命中时输出「旧值→新值」变化。
- `commands` 续写断点命中后的自动命令序列（如自动打印寄存器并 continue）。

### 观察与执行
- 内存：`x/Nbx <addr>`（十六进制）、`x/Nwx`、`x/Ngx`、`x/20i`（反汇编）、`x/s`（字符串）、`x/Nhx`（半字）。地址支持 `$rsp+0x28` 等表达式。
- 寄存器：`info registers`、`p/x $rip`，或 `info registers rip rsp rbp rax`。
- 单步：`si`（指令级）、`s`（源码级）、`ni`、`n`；`finish` 运行到函数返回；`return` 强制返回。
- 栈：`bt`、`frame N`、`info frame`、`info args`。
- 反汇编：`disassemble main`、`disassemble /r main`（含字节码）、`disassemble /m main`（混源码）。`pdisassemble`（pwndbg）泛化。

### 关键 set 项
- `set disable-randomization on/off`：默认 on（关 ASLR）。
- `set follow-fork-mode child|parent`：fork 后追哪个。
- `set detach-on-fork off`：两者都跟，`i inferiors` 切换。
- `set stop-on-solib-events 1`：在动态链接器运行时停下（分析 PLT 解析过程）。
- `set pagination off`：脚本化时关闭分页。

### 插件工作流（pwndbg / GEF / peda）
二进制安全实践中几乎必备插件（推荐 pwndbg 或 GEF，二者不可同时加载）。pwndbg 关键命令：`checksec`、`vmmap`（地址空间+权限+映射源）、`cyclic N`/`cyclic -l <val>`（De Bruijn 序列生成与偏移回溯）、`got`、`plt`、`telescope $rsp`（栈回溯视线）、`xinfo`、`heap`/`bins`/`top_chunk`/`fastbins`（堆利用专用）。GEF 对应 `gef checksec`、`gef heap`、`pattern create` 等。

## 实践示例

环境：Ubuntu 20.04 LTS x86_64、GDB 11.2、pwndbg 2023.xx、GCC 9.4.0。

```c
// dbg.c
#include <stdio.h>
void secret() { puts("secret!"); }
int main() { char buf[16]; gets(buf); printf("%s\n", buf); return 0; }
```

```bash
gcc -no-pie -fno-stack-protector -g -o dbg dbg.c
gdb -q ./dbg
```

交互会话核心步骤：

```text
pwndbg> checksec
pwndbg> break main                # 源码断点
pwndbg> run < <(python3 -c 'print("A"*16)')
pwndbg> si                        # 指令级单步，进入 vuln 序跹
pwndbg> info registers rax rbp rsp
pwndbg> telescope $rsp            # 观察栈内容
pwndbg> x/16gx $rsp
pwndbg> finish
pwndbg> disassemble /r main
```

再演示 watchpoint 定位溢出触及返回地址的瞬间（同一程序，先找偏移）：

```text
pwndbg> cyclic 100              # 生成 100 字符序列
pwndbg> run < <(echo -n <cyclic序列>)
# 崩溃于返回地址 = 序列某段
pwndbg> cyclic -l 0x61616161    # 取崩溃 RIP 对应的偏移
```

`cyclic -l` 输出即为「输入到返回地址的填充长度」，后续利用 script 的 payload 在此偏移后写目标地址。

## 常见问题与误区

- 误区一：PIE 程序用固定地址 `break *0x…`。PIE 基址随机，绝对地址断点失效；用 `break *main`（符号名）、`break *(main+N)` 相对偏移，或先 `start`/`run` 再按 vmmap 基址换算。
- 误区二：在优化代码（`-O2` 或缺 `-g`）里找旧习惯的局部变量/行号。优化使帧与变量被合并/重排，`info locals` 常显示 `<optimized out>`；此时必须回到汇编级用寄存器与栈偏移分析。
- 误区三：混淆 GDB 关 ASLR 带来的地址「假稳定」。`set disable-randomization on` 是默认值，调试态地址不能当作真实运行地址直接写进 exploit；先在真实进程里 leak 基址再做相对偏移才是通用打法。
- 提醒：`~/.gdbinit` 只应加载一个插件（pwndbg 或 GEF），两个同时 load 会互相覆盖命令导致异常。
