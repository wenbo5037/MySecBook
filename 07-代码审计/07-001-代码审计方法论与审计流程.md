# 07-001 代码审计方法论与审计流程

## 基础信息
- 难度：中级
- 前置知识：[[06-001-Web安全概览与OWASP-Top10]]
- 对应语言等级：按语言分级（Java/Go/C# 熟悉级，Python 精通级）

## 核心原理

源代码审计（Source Code Review）是对程序源码进行系统化检查，以发现安全缺陷与业务逻辑问题的过程，它与动态测试（黑盒）互补：**绿盒审计看到全部实现，动态测试验证可达性**。审计的核心方法论不是「逐行读代码」，而是**先建立数据流（Data Flow）与控制流（Control Flow）模型，再沿「污点（taint）从输入流到敏感操作（sink）」追踪**。绝大多数高危漏洞（SQL 注入、命令执行、路径穿越、XSS）本质都是污点从 source 到 sink 未被净化（sanitization）。

权威可参照的审计基准是 **OWASP Code Review Guide**（含代码审查清单）与 **OWASP ASVS**（可映射具体检查点）；工具侧成熟方案是静态分析（SAST），代表有 CodeQL（Semgrep 类规则引擎）与 SpotBugs / Bandit（Python）等，它们把「数据流可达性的判定」自动化，但人工审计的价值在于**业务逻辑漏洞**——工具几乎无法发现「逻辑缺陷」与「越权设计」。

## 技术要点

- **审计路径选择**：关键功能（认证、支付、文件处理、导出导入）优先；核心策略是「入口 → 出口」：识别所有外部输入源（HTTP 参数、文件上传、环境变量、数据库读取、反序列化输入），再追踪它们能触达的危险函数。
- **常见 sink（敏感操作）清单**：
  - SQL：字符串拼接执行（`execute/query` 拼接）、存储过程动态 SQL；
  - 命令/代码执行：`os.system`、`subprocess`（shell=True）、`eval/exec`、模板注入；
  - 文件：`open`（路径拼接 → 路径穿越）、`unlink`、ZIP 解压（Zip Slip）；
  - Web：输出未编码 → XSS；`redirect`（URL 重定向）；不安全的反序列化（`pickle`/`ObjectInputStream`）。
- **污点分析（Taint Analysis）**：source（`request.args`）→ propagation（变量传递、拼接）→ sink（`execute`）。净化检查：是否经过白名单、参数化、输出编码。
- **逻辑漏洞**：竞态（time-of-check to time-of-use, TOCTOU）、金额与库存校验顺序、越权（水平/垂直）、支付回调签名验证缺失、验证码可绕过。
- **审计产出（报告）**：漏洞标题、位置（文件:行）、CVSS 3.1 评分、影响、复现（PoC）、修复建议、严重度分级（Critical/High/Medium/Low）。参照 OWASP Risk Rating Methodology 或 CVSS 计算器（FIRST.org）。

## 实践示例

环境：Python 3.11、Bandit 1.7.x、Semgrep CLI 1.9x。

用两条工具先做自动化扫描，再人工确认污点路径。示例代码 `vuln_app.py`：

```python
import os, sqlite3
from flask import Flask, request
app = Flask(__name__)

@app.route("/run")
def run():
    cmd = request.args.get("cmd")          # source
    return os.popen(cmd).read()            # sink: 命令执行
```

```bash
pip install bandit semgrep
bandit vuln_app.py
semgrep --config p/security-audit vuln_app.py
```

Bandit 输出 `B602 subprocess_popen_with_shell_equals_true` 类告警（或 os.popen 相关），Semgrep 给出数据流路径。再用 CodeQL 对 Java 项目做污点查询（`github/codeql` 包）：

```bash
codeql database create db --language=java --source-root=./src
codeql database analyze db --format=sarif-latest --output=out.sarif \
    --download codeql/java-queries:Security-Injection
```

## 常见问题与误区

- 误区一：只跑工具不追数据流。SAST 结果需人工验证可达性与净化；正向代码（`input` 经过白名单）工具可能误报，需要源代码确认。
- 误区二：忽略框架层净化模式。ORM/`prepared statement` 会自动参数化，但「拼接 SQL 后再传 ORM」仍是注入——审计要看最终进入 sink 的字符串形态，而非 API 层是否用 ORM。
- 误区三：不测逻辑漏洞。越权、竞态、金额篡改这类缺陷在常规扫描中「无感」，必须靠人工流程（权限矩阵、并发测试、状态机推导）覆盖。
