## 核心内容

### 概念与原理

**二补数（two's-complement）**用最高位作符号位：正数不变、负数取反加一。N 位范围 [-2^(N-1), 2^(N-1)-1]（对称少一个正数）。加/减无需额外符号分支，同一加法器即可处理有符号与无符号（只需解释标志不同）。

**有符号溢出（signed overflow）**在结果超出该范围时发生，硬件用**溢出标志（OF/V）**反映：顶层进位与次高层进位不一致时置 1。这是与无符号进位（CF）完全不同的标志。

C 语言**把有符号溢出定义为未定义行为（UB）**，允许编译器对涉及假设优化的代码做激进变换（如 `x+1>x` 在 O2 下可能被判定为恒真），因此编程时必须避免依赖 UB（见[[01-14]]相关涉及编译优化）。

### 技术细节

#### 硬件判溢条件
- 加法：若两个加数同号，且结果异号 → 溢出。
- 简化：最高位进位 xor 次高位进位 = 1（OF=1）。
- 减法：`a-b` 等价 `a+(-b)`，判溢同理。

#### 二补数范围与极端
- INT_MAX+1 → 溢出为 INT_MIN（-INT_MAX-1 是 UB，虽然多数平台回绕）。
- `-INT_MIN` 也 UB。

#### 编译器视角与 UB exploitation
未定义行为赋予编译器推理自由：可删除分支、重排、假设无回绕。攻击者常利用开发者误估溢出假设：对象大小、索引、条件判断。CWE-190。

### 代码/命令示例

用 Python 模拟 4 位二补数与溢出判断：

```python
def twos4(x):          # 把任意整数映射到 4 位二补数 [-8,7]
    r = x & 0xF
    return r-16 if r >= 8 else r

def add_ovf4(a, b):
    s = twos4(a + b)
    ra, rb, rs = twos4(a), twos4(b), s
    ovf = (ra >= 0 and rb >= 0 and rs < 0) or (ra < 0 and rb < 0 and rs >= 0)
    return rs, ovf

print(add_ovf4(7, 1))   # (-8, True)  溢出
print(add_ovf4(3, 4))   # (7,  False)
```

C 中用内建检查有符号溢出：

```c
#include <stdio.h>
int main(void){
    int a = INT_MAX, r;
    if (__builtin_add_overflow(a, 1, &r))
        printf("signed overflow\n");   // 避免 UB 的判定
}
```

## 实战案例（不少于全文30%篇幅）

### 案例1：在 GCC 下观察 UB 优化改变程序行为
- 场景描述：用 `x+1 > x` 在有符号溢出下的编译优化差异演示 UB 风险。
- 环境准备：Linux + gcc
- 操作步骤：
  1. `int f(int x){ return (x+1 > x) ? 1 : 0; }`
  2. `gcc -O0` 与 `gcc -O2` 下传 `INT_MAX` 对比输出。
  3. 反汇编观察分支是否被折叠。
- 预期结果：O2 下编译器可能假设 `x+1>x` 恒真（因 UB 假设），返回 1；O0 下回绕得到 0 之类。
- 关键分析：展示“未定义行为”不仅是语言细节，而是可被优化器利用的许可，安全审查需要关注。

### 案例2：对比 CF/OF 的 Playground（Python 穷举）
- 场景描述：穷举 4 位二补数加，统计有符号溢出的组合，验证 OF 与最高/次高位进位的关系。
- 环境准备：Python 3.11+
- 操作步骤：
  1. 对 [-8,7] 全对求 `(a+b)&15` 并按符号判溢出。
  2. 与进位码 XOR 判据对比。
- 预期结果：两者完全一致。
- 关键分析：把同学交换式 `of = cout ^ cout-1` 验证为“最高位进位 xor 次高位进位”，确立硬件判据的可信性。

## 常见误区与陷阱
1. 把有符号回绕当“正常”：C 中是 UB，优化器可改变语义。
2. 混淆 CF 与 OF：判溢出要 OF（符号位进位 xor 次高位进位）。
3. 忽略条件 `INT_MIN` 的边界。
4. 依赖回绕做防御（如 `if (x < x+1)`），安全上不可靠。
