## 核心内容

### 概念与原理

**局部性原理（principle of locality）**是存储层次的理论依据：
- **时间局部性**：访问过的数据近期可能再访问（循环变量、累加器）。
- **空间局部性**：相邻数据近期可能被访问（数组顺序遍历）。

存储层次按“速度递降、容量递增、成本递减”排列：
| 层次 | 典型容量 | 典型延迟 |
|------|---------|---------|
| 寄存器 | 数百字节 | <1 周期 |
| L1 Cache | 32–64 KB | ~4 周期 |
| L2 | 256 KB–1 MB | ~12 周期 |
| L3（共享） | 2–64 MB | ~30–40 周期 |
| 主存 DRAM | 4–64 GB | ~100 ns |
| 磁盘/NVMe | TB | 数十 μs–ms |

局部性让 Cache 用相对小的容量覆盖大部分访问，命中率可达 99%+（典型程序），是实现性价比存储的关键。

### 技术细节

#### Cache 行为
命中时延迟=Cache 延迟；未命中需要向上层取回并淘汰（见[[01-22]]、[[02-08 页面置换算法对比]]）。容量/相联度/写策略影响命中率。

#### 访存路径与预取
现代处理器带硬件预取（prefetch）利用空间局部性填充行。**Cache 作为侧信道计时基础**，正是此类命中/未命中延迟差异的本质来源（见[[01-24]]）。

#### 编译器与局部性
循环换序、合并、blocking（分块）提升空间局部性。数值计算（如矩阵乘）的 cache 优化常改变性能 10 倍级。

### 代码/命令示例

用 Python 模拟统计时间局部性（命中/未命中计数）：

```python
from collections import Counter
access = [3,3,3,5,5,3,7,7,7,7]
cache, hits, refs = set(), 0, 0
for a in access:
    refs += 1
    if a in cache: hits += 1
    else: cache.add(a)
print(f"hits={hits}/{refs} ratio={hits/refs:.2%}")
```

C 演示顺序访问的 cache 友好性（perf 测量见实验）。

## 实战案例（不少于全文30%篇幅）

### 案例1：按序 vs 乱序遍历大数组的 cache miss 差异
- 场景描述：同一数组按自然序与按步长（如 stride=64）遍历，perf 观察 cache-misses。
- 环境准备：Linux + gcc + perf
- 操作步骤：
  1. 分配 64MB 数组，循环 sum 自然序。
  2. 改为每 64 跳步访问（破坏空间/时间局部性）。
  3. 分别 `perf stat -e cache-misses,cache-references` 对比。
- 预期结果：步长遍历 miss 显著更高，耗时更大。
- 关键分析：cache 行大小与预取器的存在，让跨越行间距访问付出代价——这是性能/安全（侧信道步进）都关键的量。

### 案例2：perf mem 观察内存延迟
- 场景描述：用 `perf mem record` 采样访存并查看延迟分布。
- 环境准备：Linux + perf（需特权或正确配置）
- 操作步骤：
  1. `gcc -O2` 编译矩阵乘法。
  2. `perf mem record ./a.out; perf mem report` 查看 load/store 的层次分布。
- 预期结果：多数 load 集中在 L1/L2 命中，少数遗漏到主存。
- 关键分析：把理论层次映射到真实采样，是性能优化与缓存侧信道研究的数据基础。

## 实验指南

## 常见误区与陷阱
1. 把存储层次当“缓存只有一层”：现代是四级（L1/L2/L3/点后的内存）。
2. 忽视延迟单位差异：寄存器周期、Cache 十几周期、内存百 ns、磁盘毫秒。
3. 迷信容量而忽略角落：地址转换（TLB）也是层次一员（见[[02-06]]）。
4. 以为局部性只关系性能：它是 Meltdown 侧信道的必要条件（[[01-24]]）。
