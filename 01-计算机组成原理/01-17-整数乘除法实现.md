## 核心内容

### 概念与原理

**乘法**本质是移位-相加：N 位乘法可用 N 次“移位+条件加”完成（级联行波），硬件用**组合乘法器（array multiplier）**把部分积累加并行化，或用 **Booth 算法**减少部分积数量（对连续 1 位做增量编码）。更快的 **Wallace 树 / Dadda 树**用进位保存加法器（CSA）并行缩并部分积层数。

**除法**用减法试商：逐位判断余数是否 ≥ 除数。**恢复余数法（restoring）**在减失败后加回除数；**不恢复（non-restoring）**用商位修正继续。商用除法器与乘法器相比延迟更大、吞吐更低（许多实现吞吐=每次 1 条，串行化）。

### 技术细节

#### Booth 编码
把乘数看作相邻位差分：`2^i - 2^{i-1}` 编码，当出现多个连续 1 时减少 1 的个数，降低部分积层数。Radix-4 改进进一步减半部分积行数。

#### 阵列乘法器
用与门生成全部部分积，CSA 树缩并，最后一级用 CLA 求和。关键路径≈门深乘数的 log，速度快但面积大。

#### 整数除法实现
硬件除法器通常为**串行逐位状态机**：每次迭代移位比较；恢复与否取决于余数符号。处理器按 ISA 提供 `div`/`divu`（RISC-V）或 `idiv`（x86，单一指令多周期）。

#### 与安全关系
乘法溢出（回绕）是整数缺陷高发点之一（见[[01-15]]），硬件级结果与平台回绕规则一致，但在 C 的有符号上是 UB（见[[01-16]]），需靠软件检查。

### 代码/命令示例

Python 实现移位相加乘法：

```python
def mult_shift(a, b, bits=8):
    result = 0
    for i in range(bits):
        if (b >> i) & 1:
            result += a << i
    return result

assert mult_shift(13, 5) == 65
print(mult_shift(13, 5))
```

用 objdump 观察编译器对 `*` 的优化（乘常数替换为移位+加法）：

```bash
cat > m.c <<'EOF'
int f(int x){ return x * 10; }
EOF
gcc -O2 -S m.c -o - | grep -A2 'imul\|lea'  # 观察 lea (x+x*4)*2 等模式
```

## 实战案例（不少于全文30%篇幅）

### 案例1：用 Python 实现并验证恢复余数除法
- 场景描述：逐位（restoring）实现无符号除法并与 Python 内置 `//` 对照。
- 环境准备：Python 3.11+
- 操作步骤：
  1. 按教材实现 8 位恢复余数除法 AMD 方式（左移余数、减除数）。
  2. 对若干随机数 assert `q==a//b and r==a%b`。
- 预期结果：穷举少量样本全部正确。
- 关键分析：把算法落到可执行代码，验证位级语义；理解除法为何比乘法慢（需串行修复）。

### 案例2：反汇编观察硬件乘法 vs 编译器常量乘法
- 场景描述：对比 `x*10`（常数）与运行时 `a*b` 的 x86 指令，理解 Booth/阵列在芯片中的体现。
- 环境准备：Linux + gcc + objdump
- 操作步骤：
  1. 编译 `int g(int a,int b){return a*b;}` 与 `int f(int x){return x*10;}`。
  2. 反汇编：`a*b` → `imul`（硬件乘法单元）；`x*10` → `lea` 三指令展开。
- 预期结果：运行时乘法用 `imul`，常量乘法被编译器拆为移位+加法。
- 关键分析：硬件乘法器存在的必要性（运行时值才需要），常量乘法的拆解体现编译器对 ALU 的利用。

## 常见误区与陷阱
1. 认为乘除法只是加法循环：硬件有专门乘法器与除法状态机。
2. 忽略有符号与无符号乘除使用不同指令（如 x86 `imul`/`mul`）。
3. 把硬件乘法器吞吐与延迟混淆：流水化可按周期平均一条。
4. 忘记宽余数/中间结果的位宽处理（如 64 位乘法需 128 位中间积）。
