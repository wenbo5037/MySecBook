## 核心内容

### 概念与原理

**无符号整数（unsigned）**二进制位全为数值位，N 位范围 [0, 2^N − 1]。加减在没有进位/借位时正确；最高位产生**进位（carry）**时加法**上溢（wrap around）**，减法需要借位时**下溢**，结果模 2^N。

在 ALU 中，无符号溢出由**进位标志**反映：
- 加法：若最高位向更高位进位 → 上溢（Carry=1）。
- 减法：若最高位借记位（B>A）→ 下溢（Borrow=1，硬件用进位取反实现）。

C 语言的无符号运算**定义了回绕**（modulo），不触发未定义行为——但**不意味着没有安全后果**：回绕后数值可能错误且巨大（如缓冲区长度计算）。

### 技术细节

#### 判溢公式
- 无符号加：`(unsigned)a+b` 溢出 ⇔ `carry_out=1` ⇔ 结果 < a（因加法结果一定≥任一加数；若回绕则小于）。
- 无符号减：`a-b` 下溢 ⇔ `a < b`（属正常比较）。

#### 与有符号的区别
有符号用**溢出标志 V**（符号位进位≠最高位进位）判断，见[[01-16]]。RF 语义与标志位在指令集中独立存在（如 x86 的 CF 与 OF）。

#### 攻击面
无符号回绕常出现在大小计算、偏移量累加、下标换算中：
```c
size_t total = size_a + size_b;   // 回绕 → 后续 malloc 过小 → 堆溢出
```
CWE-190/191 与缓冲区溢出是此类漏洞高发区；C/C++ 需要用 `size_t` 合理、`__builtin_add_overflow` 或宽类型防御。

### 代码/命令示例

Python 验证无符号回绕与进位（Python 3.11+）：

```python
W = 4  # 4 位
def add_4(a, b):
    s = a + b
    carry = 1 if s >= (1 << W) else 0
    return s & ((1 << W) - 1), carry

print(add_4(0b1111, 0b0001))   # (0, 1) → 15+1 溢出
print(0b1100 + 0b1010)          # 12+10=22 → 超出4位，模拟得到6，carry1
```

C 用内建溢出检测：

```c
// gcc 13+ 内置溢出检查
size_t a = SIZE_MAX, b = 1, r;
if (__builtin_add_overflow(a, b, &r)) {
    printf("unsigned overflow detected\n");
}
```

## 实战案例（不少于全文30%篇幅）

### 案例1：复现经典的 size 回绕堆溢出
- 场景描述：用 `size_t` 加法回绕构造缓冲区长度错误，验证漏洞模式并修复。
- 环境准备：Linux + gcc
- 操作步骤：
  1. 写 `size_t sz = a + b; char *p = malloc(sz); memcpy(p, src, a*b);` 的反智示例。
  2. 设 `a=SIZE_MAX/2`, `b=2` 使 `a+b` 回绕为小值。
  3. 用 `__builtin_add_overflow` 检测并拒绝过大请求。
- 预期结果：未修复时 malloc 分配过小缓冲区，memcpy 越界写（演示需在授权环境/沙箱）。
- 关键分析：这是 CWE-190 → 堆溢出的经典链条；防御应在上层做长度边界校验，而非依赖 malloc 检查。

### 案例2：用 Python 穷举验证回绕边界
- 场景描述：对 4 位无符号加/减穷举，验证 carry/borrow 判定与回绕公式一致。
- 环境准备：Python 3.11+
- 操作步骤：
  1. 对 0..15 全部 a,b 计算 `(a+b)&15` 与“结果<a 即 carry”。
  2. 对减法 assert 下溢条件 `a<b`。
- 预期结果：断言全部通过。
- 关键分析：用穷举法验证硬件/语言语义，也是做安全性质验证（property testing）的入门模式。

## 常见误区与陷阱
1. 认为回绕“无害”：它只保证语言行为，可导致真实越界。
2. 把所有溢出都当有符号判断：需先确定有符号/无符号语义。
3. 忽视 size_t 与 int 混用时的隐式转换（可能导致符号错误）。
4. 只在减法上用借位：加法进位同样需处理。
