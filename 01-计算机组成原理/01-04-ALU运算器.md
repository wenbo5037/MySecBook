## 核心内容

### 概念与原理

**ALU（Arithmetic Logic Unit）**是 CPU 的运算核心，负责加减、与或异或、移位、比较等操作。它接收两个操作数 A、B 和一个**操作选择信号（ALUOp）**，输出结果 R 与状态标志（Zero、Carry、Overflow、Negative）。

三种进位设计：
- **行波进位加法器（Ripple Carry）**：全加器链式传播进位，延迟 O(N)，N 位加法最坏需 N×Δc 延迟。
- **超前进位（Carry Lookahead）**：用生成项 G=A·B 与传播项 P=A⊕B 并行计算各进位，延迟 O(log N)，是高频 CPU 的基础。
- **进位选择/进位保存**：进一步的面积-延迟折中与乘法（见[[01-17]]）配合。

### 技术细节

#### ALU 控制信号与标志
典型 ALU 接口：
```
A[N-1:0], B[N-1:0]         # 输入操作数
ALUOp[2:0]                 # 000 AND, 001 OR, 010 ADD, 110 SUB, 101 SLT, …
R[N-1:0], Zero, Carry, Overflow, Neg   # 结果与标志
```

#### 减法：全减器或取反加一
减法 A−B 用「A + (B 取反) + 1」一步完成，进位输出取反即得借位；加/减共用同一加法器，仅输入端多一个 2-1 MUX 与反相器。

#### 有符号与无符号
有符号比较与无符号比较使用不同标志：slt/sltu 在 RISC-V 中分别由溢出标志与进位标志驱动，是[[01-15]]、[[01-16]]溢出话题的前置。

### 代码/命令示例

用 Python 模拟 4 位 ALU 加减（Python 3.11+）：

```python
def alu_op(a, b, op):
    if op == "add":
        return (a + b) & 0xF
    elif op == "sub":
        return (a - b) & 0xF
    elif op == "and":
        return a & b
    elif op == "or":
        return a | b

print(alu_op(0b1010, 0b0111, "add"))   # 0b10110 → 0x6? 末4位
print(alu_op(0b1010, 0b0111, "sub"))
```

## 实战案例（不少于全文30%篇幅）

### 案例1：用 Logisim 搭建 4 位超前进位加法器
- 场景描述：手工搭建 CLA 并用多组输入验证与手算一致，比较与行波进位的延迟。
- 环境准备：Logisim-evolution 2.7.x
- 操作步骤：
  1. 计算各全加器的 P、G。
  2. 用层层组的 P、G 生成进位 Ci 再送入加法。
  3. 连线并对输入 A、B 与进位输入穷举 4~5 组测试。
- 预期结果：同输入下 CLA 与行波进位结果完全一致。
- 关键分析：用层次结构（分组 CLA）把延迟从链式线性降到对数级，是高性能 ALU 与乘法器的核心技巧。

### 案例2：C 代码观察 ALU 标志（进位/溢出）编程
- 场景描述：用 C 与内联汇编观察 unsigned/signed 溢出标志的设置，为溢出专题（[[01-15]]、[[01-16]]）做铺垫。
- 环境准备：Linux + GCC 13+
- 操作步骤：
  1. unsigned 加法用进位标志判断进位，用 `__builtin_add_overflow` 检查。
  2. signed 相加用 V 标志判断溢出，对比 `__builtin_add_overflow` 结果。
- 预期结果：`UINT_MAX+1` 进位且结果为 0；`INT_MAX+1` 溢出且结果为负（符合二补数）。
- 关键分析：ALU 的 Zero/Carry/Overflow 是多语言编译后端（见[[01-15]]）与安全编码（未定义行为）的底层依据。

## 常见误区与陷阱
1. 把 ALU 运算当“全并行”：长度大时行波进位延迟显著。
2. 混淆进位与溢出：无符号用借位/进位，有符号用溢出标志。
3. 忽略 Zero 标志在分支（beq/bne）中的复用。
4. 误以为 ALU 只有加减法——移位与位操作同样属于 ALU 范围。
