## 核心内容

### 概念与原理

**寄存器（Register）**是并排的一组 D 触发器，在同一时钟边沿统一锁存 N 位数据，是 CPU 最快的存储。**寄存器文件（Register File）**是 CPU 内一组寄存器组成的数组，通常提供多读多写端口以支持后续流水线（见[[01-10]]）中一周期内同时读两个操作数、写一个结果。

**总线（Bus）**是一组共享的传输线路，分为三类：
- 数据总线：双向传数据，宽度决定一次传输的位数（如 64 位）。
- 地址总线：由 CPU 单向输出目标地址，宽度决定可寻址空间（地址线 N 根可寻址 2^N 字节）。
- 控制总线：传送读/写、时序、中断等控制信号。

总线允许多个设备共享线路，但同一时刻只能有一个设备驱动——由**三态缓冲器（tri-state buffer）**与**仲裁（arbitration）**机制保障（多数设备输出呈高阻态 Z，仅选中者置有效电平）。

### 技术细节

#### 寄存器文件端口
典型 RISC-V 寄存器文件（见[[01-08 指令集架构总览]]）含：2 个读地址与读数据口（rs1、rs2），1 个写地址与写使能口（rd）。写采用时钟沿，读为异步组合输出。

#### 总线仲裁
集中式（专用仲裁器又称总线控制器）与分布式（菊花链）两类。PCI/PCIe 演进（详见[[01-22]]总线相关）体现了从并行共享总线到高速串行点对点链路的趋势。

#### 三态与共享
任何时刻至多一个主设备在总线上发送有效数据；多个设备同时驱动会导致总线竞争（bus contention），可能烧毁电路。CPU、DMA（见[[02-12]]）、外设均需按仲裁协议轮流占用总线。

### 代码/命令示例

用 Python 模拟寄存器文件与三态总线行为（Python 3.11+）：

```python
class RegisterFile:
    def __init__(self, n=8):
        self.reg = [0] * n
    def read(self, r):
        return self.reg[r]
    def write(self, r, v, we):
        if we:
            self.reg[r] = v

rf = RegisterFile()
rf.write(3, 42, True)   # 写使能为真
print(rf.read(3))        # 42
print(rf.read(3) if False else "高阻态? 未选中则视为无驱动")
```

## 实战案例（不少于全文30%篇幅）

### 案例1：Logisim 构建 2 位寄存器文件
- 场景描述：用 4 个 D 触发器实现 2×2 位寄存器文件，带读/写使能，观察写入时序。
- 环境准备：Logisim-evolution 2.7.x
- 操作步骤：
  1. 放置 4 个 D 触发器，每 2 个一组构成 2 位寄存器。
  2. 用 2-4 解码器 + 写使能控制各寄存器写入。
  3. 用 4-1 MUX 选择读出的寄存器，接到 2 位显示。
- 预期结果：写使能时才更新目标寄存器，读选择正确率 100%。
- 关键分析：把触发器数组、解码器、MUX 组合成寄存器文件的完整映射，为 ALU 数据通路（见[[01-04]]）提供寄存器堆。

### 案例2：Linux 上观察寄存器与内存速度差距
- 场景描述：通过 C 程序对比寄存器级运算与内存访问的延迟量级，理解存储层次。
- 环境准备：任意 Linux（GCC 13+）
- 操作步骤：
  1. 写循环对寄存器变量自加与对 mmap 内存读写，用 `clock_gettime` 计次。
  2. 编译运行 `gcc -O2` 观察二者耗时差异。
- 预期结果：寄存器操作可达纳秒级，内存访问因 cache 命中差异明显（见[[01-21]]）。
- 关键分析：寄存器是最快存储，其稀缺性决定了 CPU 指令集的寄存器数量很少，这也是体系结构安全（如 Meltdown 训练依赖寄存器相关延迟侧信道）的基础。

## 常见误区与陷阱
1. 认为寄存器与锁存器等价：寄存器是边沿触发的一整组同步锁存。
2. 忽略三态缓冲器的 Z 状态：多个设备驱动虽码是常见硬件故障。
3. 混淆地址总线宽度与数据总线宽度对寻址空间的贡献。
4. 忘记寄存器文件写是边沿时序，读是组合输出。
