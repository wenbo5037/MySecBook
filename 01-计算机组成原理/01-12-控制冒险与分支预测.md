## 核心内容

### 概念与原理

**控制冒险（control hazard）**发生在分支指令：取指方向（跳转或顺序）要到 EX 阶段计算后才确定，而后续指令已按旧方向预取。解决方式：
- 停顿（stall）：等分支判定，浪费气泡。
- 静态分支预测：恒“不跳”或“跳”，简单但命中率有限。
- **动态分支预测**：基于历史行为预测方向，用 **BTB（Branch Target Buffer）** 缓存目标地址。

现代高性能处理器把分支预测做成多级/多组件流水线，预测错时冲刷（flush）误猜指令并回滚，代价为整条流水排出（penalty ≈ 几十周期）。

### 技术细节

#### 预测器架构
- **2-bit 饱和计数器**（Bimodal）：四态 强不取/弱不取/弱取/强取，抑制抖动。
- **全局/局部历史混合**：Branched History 与 Pattern History Table 组合（如 gshare），可关联分支之间的相关性。
- **BTB**：Key=PC，记录最近跳转目标；分支目标无 BTB 时用相对偏移计算。
- **RAS（Return Address Stack）**：预测 return 指令的目标，由堆栈镜像维护。

#### 误预测代价
流水线在分支判定失败时冲刷已取出指令并回滚寄存器更新。代价 ≈ 冲刷深度（级数）个周期的 IPC 损失。高分支密度代码（如大量函数调用）考验预测器准确率。

#### 与安全（Spectre）的关系
分支预测为侧信道提供了“训练”窗口：攻击者可训练预测器使其误判（如[[01-24]]），利用推测执行的旁路副作用泄露数据。因而预测器不仅是性能部件，也是安全研究核心面。

### 代码/命令示例

用 Python 模拟 2-bit 预测器：

```python
class Bimodal:
    def __init__(self):
        self.state = {}  # 每分支 PC -> 0..3
    def predict(self, pc):
        return self.state.get(pc, 2) >= 2  # 默认“取”
    def update(self, pc, taken):
        s = self.state.get(pc, 2)
        s = min(3, s+1) if taken else max(0, s-1)
        self.state[pc] = s

p = Bimodal()
for taken in [True, True, True, False, True]:
    print(p.predict(0), taken); p.update(0, taken)
```

## 实战案例（不少于全文30%篇幅）

### 案例1：perf 测量分支误预测率
- 场景描述：对一个随机数据驱动的分支程序测 branch-misses 并分析跳变分支的影响。
- 环境准备：Linux + perf
- 操作步骤：
  1. 写循环按 `arr[i] > 50` 分支累加（预排序 vs 乱序）。
  2. `perf stat -e branch-misses,branches ./a` 各测两次。
  3. 比较误预测率（misses/branches）。
- 预期结果：随机/无序数据误预测率明显高于有序数据（预测器无法学习随机序）。
- 关键分析：预测误判率直接解释 IPC 差异，也是 Spectre 训练分支的物理基础（[[01-24]]）。

### 案例2：反汇编 + 手算 BTB 影响
- 场景描述：观察一个 `for` 循环反汇编，识别回跳分支（back-edge）并分析其预测性。
- 环境准备：Linux + objdump
- 操作步骤：
  1. `gcc -O2 -S` 编译一个循环。
  2. 找循环末尾的条件跳转（如 `jne` 回跳），推测其 2-bit 状态演变。
  3. 对比 `switch` 与 `if-else` 的分支密度。
- 预期结果：回跳分支高度可预测；switch 密集可能触发多级预测。
- 关键分析：理解分支结构如何决定预测困难度，该洞察对逆向还原与性能优化同样有用。

## 常见误区与陷阱
1. 以为现代预测器只有一个计数器：实际为多级混合预测。
2. 忽视 speculation 的安全性：预测器是可训练的一侧信道（Spectre）。
3. 把 BTB 与分支历史表混为一谈：一个存目标、一个存历史模式。
4. 误以为循环必然可预测：数据相关分支（不固定方向的回跳）反例存在。
