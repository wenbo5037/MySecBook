## 核心内容

### 概念与原理

多核共享主存、每核有私有 Cache，必须保证**缓存一致性（cache coherence）**：任何时刻对同一地址的读都能看到某个写序。**MESI** 是经典协议，行为通常用**缓存窥探（snooping）**实现：每个核心监视总线上其他核心对共享行的写请求，据此更新本地状态。

四种状态：
- **M（Modified）**：本核独占地写了，与主存不一致，是唯一有效副本。
- **E（Exclusive）**：本核独占读，与主存一致，无其他副本。
- **S（Shared）**：多核只读副本，且与主存一致。
- **I（Invalid）**：无效，不持有有效数据。

### 技术细节

#### 关键转换
| 事件 | 转换 |
|------|------|
| 本地读，无副本 | → E |
| 本地写 E | → M |
| 远端读 M 的行 | M → S（回写主存） |
| 远端写 M 的行 | M → I（失效本地） |
| 本地写 S | → M（需先 invalidate 其他） |
| 远端写 S/E | → I |

总线操作：`Read`（求副本）、`Write/Invalidate`（写并置他人 I）。**有效性（invalidate）消息**让持有副本的核心丢弃。

#### 与内存模型
一致性（coherence）只保证顺序一致（sequential consistency）的一条：写序与一致性序一致。**宽松内存模型（relaxed）**再把写序进一步放宽，由硬件（如 x86 TSO、ARMv8 弱序）与内存屏障约束。这直接影响并发编程正确性与 side-channel（如推测读）。

#### 攻击面与工具
- **缓存计时侧信道**依赖行状态与授权：Flush+Reload 用共享 S 行测进面访问（攻击者与受害者共享 cache 行）。
- **CLFLUSH 与 RDTSC** 是测量 Cache 行存在/缺失的工具指令。

### 代码/命令示例

Python 模拟 MESI 核心转换（简化 2 核）：

```python
class Core:
    def __init__(self):
        self.cache = {}   # addr -> 'M','E','S','I'
    def local_write(self, addr):
        st = self.cache.get(addr, 'I')
        self.cache[addr] = 'M'                 # 写前需其他核 invalidate
        return f"write {addr}: {st}->M"
    def remote_read(self, addr):
        st = self.cache.get(addr, 'I')
        if st == 'M':
            # 回写并使本地降为 S
            self.cache[addr] = 'S'
            return "remote read on M: ->S (writeback)"
        return None
    def remote_wr(self, addr):
        self.cache[addr] = 'I'

a = Core(); b = Core()
print(a.local_write(0x10))
print(b.remote_read(0x10))   # a 从 M → S
```

## 实战案例（不少于全文30%篇幅）

### 案例1：多线程一致性场景验证
- 场景描述：两个核心交替读写共享整数，不加锁观察乱序，加同步后验证一致。
- 环境准备：Linux + GCC + 原子/内存屏障示例
- 操作步骤：
  1. 单线程顺序写读正常。
  2. 两线程竞争共享 x，用 `__atomic` 与显式 barrier 进行访问。
  3. 反汇编观察 `MFENCE`/`LOCK` 的位置。
- 预期结果：无同步时结果不确定；加屏障后确定。
- 关键分析：MESI 只保证协议层面一致，程序员还需见内存模型使用屏障——这正是漏洞（数据竞争）的温床。

### 案例2：Flush+Reload 计时（概念演示）
- 场景描述：用 CLFLUSH + 计时观察共享行的命中差异，体现 MESI 状态可观测。
- 环境准备：Linux + 高性能计时（rdtsc）+ 授权环境
- 操作步骤：
  1. 共享一个行变量，`clflush(&x)` 后再计时重读。
  2. 对比未 flush 时重复读的时间差。
- 预期结果：flush 后首读变慢（cache miss），连续读很快。
- 关键分析：MESI/缓存状态的“命中-缺失”差异可量化，这正是 Spectre 加载侧信道（[[01-24]]）的测量部件；实验需在授权沙箱进行。

## 常见误区与陷阱
1. 混淆一致性与顺序一致：coherence 不要求存在全局写序之外还要求 reads-your-writes 等。
2. 以为 MESI 是唯一协议：MOESI（AMD）、MSI、Dragon 等在扩展。
3. 忽略写回时机：M→S 的回写由远端读触发，主动回写未必。
4. 把 cache 缺失当唯一侧信道：时序还受预取与虚拟内存影响。
