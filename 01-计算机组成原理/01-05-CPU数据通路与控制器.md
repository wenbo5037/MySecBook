## 核心内容

### 概念与原理

**数据通路（Datapath）**是 CPU 中数据流动经过的部件集合：PC 寄存器、指令存储器、寄存器文件、ALU、数据存储器、立即数扩展器与各类 MUX。**控制器（Control）**根据指令的操作码（opcode/funct3/funct7）产生控制信号，指引数据通路按指令语义动作。

单周期设计：每条指令在一个时钟周期内完成。数据通路由以下阶段组成：
1. **取指 IF**：PC 指向指令存储器，取出指令（`Instruction[31:0]`）。
2. **译码 ID**：拆出 rs1、rs2、rd、立即数；生成控制信号。
3. **执行 EX**：ALU 运算与地址计算。
4. **访存 MEM**：Load/Store 访问数据存储器。
5. **写回 WB**：把结果写回寄存器文件。

### 技术细节

#### 典型控制信号
| 信号 | 作用 | 取值 |
|------|------|------|
| RegWrite | 写寄存器文件 | 1 时写入 rd |
| ALUSrc | 选择立即数或 rs2 作为 ALU 输入 B | 0=rs2, 1=imm |
| MemRead/MemWrite | 控制数据存储器 | 仅 Load/Store |
| MemtoReg | 选择回写数据来源 | 0=ALU, 1=存储器 |
| Branch | 分支是否生效 | 仅 beq/bne |
| ALUOp | ALU 操作类别 | 00 加、01 减、10 由 funct3 决定 |

#### RISC-V 指令编码要点
R 型：`funct7 | rs2 | rs1 | funct3 | rd | opcode`；I 型含 12 位立即数；S 型与 B 型立即数字段拆分。控制器需要 funct3/funct7 扩展以精确决定 ALU 操作（RISC-V 用 FUNCT 辅助译码器）。

#### 单周期 vs 多周期
单周期周期长度由最慢指令（Load）决定，硬件利用率低；多周期把每条指令拆成多个状态，改用共享 ALU 与内部寄存器，硬件更省但每周期有额外延迟与控制状态机。现代流水线（见[[01-10]]）是在此基础上细分阶段实现并行。

### 代码/命令示例

用 Python 模拟单周期控制信号的生成（Python 3.11+，仅示 key 表）：

```python
def control(opcode):
    c = {"RegWrite":0,"MemRead":0,"MemWrite":0,"ALUSrc":0,"MemtoReg":0,"Branch":0,"ALUOp":0}
    if opcode == "lw":   # 0110011
        c.update({"RegWrite":1,"MemRead":1,"ALUSrc":1,"MemtoReg":1,"ALUOp":0})
    elif opcode == "sw":
        c.update({"MemWrite":1,"ALUSrc":1,"ALUOp":0})
    elif opcode == "add":
        c.update({"RegWrite":1,"ALUOp":2})
    return c

print(control("lw"))  # 对照教材真值表核对
```

## 实战案例（不少于全文30%篇幅）

### 案例1：Logisim 搭建最小单周期 CPU（仅 add/lw/sw/beq）
- 场景描述：手工布线一个支持 4 条指令的极简数据通路，理解取指-执行闭环。
- 环境准备：Logisim-evolution 2.7.x
- 操作步骤：
  1. 放置 PC 寄存器、指令 ROM、寄存器文件、ALU、数据 RAM。
  2. 实现符号扩展与 MUX 选择立即数/寄存器。
  3. 实现分支 MUX（PCSrc = Branch & Zero）。
  4. 用 ROM 内嵌 3 条指令运行单步。
- 预期结果：add/lw/sw 序列在指令 ROM 中按序号执行，最终寄存器与内存一致。
- 关键分析：单周期控制器真值表 + 数据通路的对照是本篇核心；顺序执行失效的分支跳转需处理 beq 目标计算。

### 案例2：编译真实指令观察控制流
- 场景描述：用 GCC 编译 C 循环为汇编，反汇编对照 beq 的目标与数据通路依赖。
- 环境准备：Linux + GCC 13 + objdump
- 操作步骤：
  1. `gcc -S` 编译一个 for 循环。
  2. `objdump -d` 观察 beq 与 ALU 使用的指令序列。
- 预期结果：循环体呈现 ADD/SUB + beq 的组合，分支目标为相对偏移。
- 关键分析：把理论通路映射到真实机器码，为后续流水线分支预测（[[01-12]]）奠定语义基础。

## 常见误区与陷阱
1. 混淆数据通路上的 MUX 作用：ALUSrc、MemtoReg 选择不同数据源。
2. 误以为 PC 每周期都 +4：分支指令需计算跳转目标并选 PC 来源。
3. 忘记立即数符号扩展对 beq 地址计算的影响。
4. 把 Load 回写路径与其他指令回写混淆，Mis 用 MemtoReg 区分。
