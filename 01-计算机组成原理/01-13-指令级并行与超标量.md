## 核心内容

### 概念与原理

**指令级并行（ILP）**指指令流中存在可同时执行的独立指令。提升 ILP 的手段：
1. **超标量（Superscalar）**：每周期发射多条（N 路）指令到多个执行单元。
2. **乱序执行（Out-of-order）**：放宽指令顺序约束，动态调度独立指令。
3. **超长指令字（VLIW）**：编译器静态打包多条运算到一条指令（如 Itanium/EPIC，已少用）。

Hennessy & Patterson 定义“每时钟周期平均完成指令数（IPC）”为关键指标。现代 x86/ARM 处理器为 4~8 发射、10+ 执行单元。

### 技术细节

#### 发射与执行资源
- **发射端口（issue port）**：每周期最多发射 N 条，前端与后端之间通过**指令队列（window）**连接。
- 执行单元分工：整数 ALU、FP/向量、load/store、分支。**结构冒险**限制多发射（端口冲突）。

#### 静态 vs 动态调度
| | 静态调度（编译器） | 动态调度（硬件） |
|---|---|---|
| 时序决策 | 编译时 | 运行时（保留站/rob） |
| 硬件复杂度 | 低 | 高 |
| 未知运行信息 | 无法利用 | 可适应 cache miss 等 |

实际处理器混用：编译器负责重排、硬件乱序调度窗口内指令。

#### ILP 极限
Load 延迟、分支失败、资源限制（功能单元带宽）共同决定实际 IPC 远低于理论峰值（Amdahl 类瓶颈）。**Trace cache / 宏融合**等技巧提高发射率。

### 代码/命令示例

用 Python 找出可并行指令对（模拟一个 2-发射窗口）：

```python
def parallelizable(seq):
    w = []
    for inst in seq:
        deps = any(r in inst["uses"] for prev in w for r in prev["defs"])
        if not deps and len(w) < 2:
            w.append(inst)
        else:
            yield w[:]; w=[inst]
    if w: yield w

for bundle in parallelizable([
    {"defs":["t1"],"uses":["a","b"]},
    {"defs":["t2"],"uses":["c","d"]},
    {"defs":["t3"],"uses":["t1","t2"]},
]):
    print(bundle)
```

## 实战案例（不少于全文30%篇幅）

### 案例1：用 perf 观察不同数据依赖下的 IPC
- 场景描述：编译两个循环（依赖链长 vs 独立加法）对比 IPC，验证 ILP 上限。
- 环境准备：Linux + perf
- 操作步骤：
  1. 循环 A：`sum += x[i]`（串行依赖加法）。
  2. 循环 B：4 独立累加再合并。
  3. 分别 `perf stat -e cycles,instructions` 测 IPC。
- 预期结果：独立版本 IPC 更高（受发射宽度与依赖约束控制）。
- 关键分析：IPC 与 ILP 的关系量化体现了发射/依赖窗口的作用，反副作用推测执行攻击（见[[01-24]]）也依赖“可重叠执行的指令”。

### 案例2：编译器自动向量化与超标量的配合
- 场景描述：观察 GCC 对数组求和自动向量化（SIMD）的汇编，理解 ILP 与向量并行互补。
- 环境准备：Linux + gcc + objdump
- 操作步骤：
  1. `int s(int *a,int n){int r=0; for(...) r+=a[i]; return r;}` 用 -O3 -march=native。
  2. `objdump` 找 SIMD 指令（如 `vpaddd`），对比非向量版本。
- 预期结果：出现打包加法指令，单指令多数据元素同时操作。
- 关键分析：SIMD 是一种数据级并行（DLP），与 ILP 互补，共同决定现代处理器吞吐上限。

## 常见误区与陷阱
1. 认为超标量 = 乱序：二者正交，可单独存在。
2. 把 IPC 当固定值：受负载与依赖分布影响极大。
3. 忽略发射宽度 vs 执行单元数：发射是入口，执行瓶颈可能在资源。
4. 以为 VLIW 是主流现代方法：仅特定嵌入/GPU 保留，通用 CPU 用乱序。
