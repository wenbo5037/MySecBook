## 核心内容

### 概念与原理

**流水线（Pipeline）**借鉴工业生产：把指令执行切分为多个阶段，各阶段在同一时钟沿并行为不同指令服务。经典五级：IF → ID → EX → MEM → WB，级间用**管线寄存器**（IF/ID、ID/EX、EX/MEM、MEM/WB）暂存数据，形成流水。理想情况下每个时钟周期完成一条指令，吞吐=1 IPC；但延迟（单条指令耗时）不变，且存在冒险限制。

- **吞吐**：1/T_clk（每周期一条）。
- **延迟**：N 级 × T_clk。
- **加速比**：理想 = 级数 N；实际因冒险与停顿（stall）降低。

### 技术细节

#### 管线寄存器内容
ID/EX 保存指令、控制信号、读取的寄存器值；EX/MEM 保存 ALU 结果、分支目标、写数据；MEM/WB 保存最终写回值。这些寄存器是数据冒险转发的基础（见[[01-11 数据冒险与前递]]）。

#### 冒险分类
1. **结构冒险**：同一部件被两条流水差冲突（如单存储器同时取指与访存）。
2. **数据冒险**：下条指令需要上条尚未写回的结果。
3. **控制冒险**：分支取指方向未知，需停顿或预测（见[[01-12]]）。

#### 停顿与气泡
无法转发/预测时插入 no-op 气泡，降低 IPC；**打分板（scoreboard）**与 **Tomasulo 算法**（见[[01-14]]）把冒险处理推进到乱序。

### 代码/命令示例

用 Python 模拟 3 条流水线的时序表格：

```python
stages = ["IF","ID","EX","MEM","WB"]
instr  = [f"I{j}" for j in range(3)]
for t in range(7):
    row=[]
    for i,ins in enumerate(instr):
        if i <= t < i+5:
            row.append(f"{ins}:{stages[t-i]}")
    print(f"cycle{t}: "+"  ".join(row) if row else f"cycle{t}: (idle)")
```

输出显示各指令在周期内占据的阶段，理解重叠。

## 实战案例（不少于全文30%篇幅）

### 案例1：Logisim 实现 2 级简化流水线
- 场景描述：在一个最小支持 add 的 CPU 上加入级间寄存器，观察指令在流水中的重叠执行。
- 环境准备：Logisim-evolution 2.7.x
- 操作步骤：
  1. 在单周期通路中插入 IF/ID 与 ID/EX 管线寄存器。
  2. 使 PC 提前更新，观察两条 add 的重叠。
  3. 用 ROM 放两条顺序 add 指令并运行。
- 预期结果：cycle0 取指 I0、cycle1 同时译码 I0 并取指 I1，形成重叠。
- 关键分析：即使只有 2 条指令，也能直观看到 IF 与 EX 并行——这是后续冲突解决（转发、旁路）的基础场景。

### 案例2：Linux 用 perf 观察 IPC
- 场景描述：运行一个计算密集程序并用 `perf stat` 观察 IPC（每周期指令数）。
- 环境准备：Linux + perf
- 操作步骤：
  1. `perf stat -e cycles,instructions ./bench >/dev/null`
  2. 计算 IPC = instructions/cycles，与理想 4~6 比较观察未达理想的原因（冒险/访存）。
- 预期结果：IPC 通常明显低于理论峰值。
- 关键分析：真实 CPU 的 IPC 受 load 延迟、分支失败、乱序窗口等限制，帮助理解流水线理论如何落水。

## 常见误区与陷阱
1. 以为流水线能减少单条指令延迟：它增加或维持延迟、提升吞吐。
2. 忽略结构冒险：单一存储器无法同时取指与访存。
3. 把气泡当规范：气泡只用于无法转发的极端情况。
4. 误把 IPC 指标当理想值而忽视负载。
