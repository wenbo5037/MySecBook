# 网络安全知识库 README

网络安全知识库的总入口与使用说明。本知识库采用 Tolaria 管理，通过类型、编号、wikilink 关系组织内容；文件目录仅用于按领域分区浏览，不是内容组织的唯一来源。

## 一、知识库定位

面向「二进制安全、物联网安全、红蓝对抗、AI 安全、安全开发」为核心主攻方向的安全学习与实践知识库，同时覆盖 Web 安全、代码审计，以及云计算与运维基础。内容同时服务于新手（入门篇）与从业者（进阶/高级篇），所有结论真实可查、示例可复现。

说明：

- 每个领域文件夹内存放该领域的领域页（如 `01-二进制安全/二进制安全.md`）与全部编号文档。
- 文档统一命名 `[领域编号]-[三位序号]-主题名称.md`。
- 新建文档默认存放于对应领域文件夹；未归类的临时笔记会出现在 Vault 根目录，随后应归入对应领域。

## 三、编号与命名规则

- 编号格式：`[领域编号]-[三位序号]`，例如 `01-004` 代表第 1 领域（二进制安全）第 4 篇。
- 领域编号：01 二进制安全 / 02 物联网安全 / 03 红蓝对抗 / 04 AI安全 / 05 安全开发 / 06 Web安全 / 07 代码审计 / 08 云计算与运维基础。
- 生成顺序：基础 → 进阶 → 高级；核心主攻领域推进 70% 后并行生成次核心，最后生成入门领域。
- 自动按知识依赖关系排序，前置主题编号记入每篇的「前置知识」字段，避免重复、跳跃与缺失。

## 四、单篇文档模板

每篇正文严格按以下章节顺序，不得缺章、不得调序：

```markdown
# [编号] 主题名称
## 基础信息        # 难度 / 前置知识 / 对应语言等级
## 核心原理        # 技术本质、设计逻辑，关键点随文标注权威来源
## 技术要点        # 细节、参数、机制，禁止泛泛而谈
## 实践示例        # 可复现命令/代码/步骤，标注工具版本与环境
## 常见问题与误区  # 2-3 个最易踩的坑
## 参考来源        # 2-3 个权威来源：「名称 - 类型 - 出处」
## 合规声明        # 仅涉及攻击技术的文档
```

字数要求：单篇正文 ≥800 字，≤4500 字；重要主题建议 3000–4500 字；内容可拆分的主题拆分独立成篇，不合并堆砌。

## 五、语言分级与内容深度

| 等级 | 语言 | 深度标准 |
|------|------|----------|
| 精通级 | C/C++、汇编、Python | 底层实现、源码级漏洞、完整可利用代码、中大型项目实践 |
| 熟悉级 | Java、Go、C#、前端、PHP | 核心安全特性、常见漏洞模式、安全编码规范、中型项目实践 |
| 入门级 | Rust、Node.js、Android、iOS | 基础语法安全点、部署方法、漏洞入门认知 |

## 六、质量铁律

1. 真实性：工具、CVE、参数、代码必须真实可查，禁止编造；不确定内容标注「待验证」。
2. 权威性：核心结论必有权威来源支撑，优先官方文档 → 权威标准 → 开源项目 → 经典教材。
3. 实战性：每篇含可复现实践，标注版本号与环境。
4. 分级适配：语言深度严格对应等级。
5. 合规性：攻击技术仅限授权测试场景，文末附合规声明。

## 七、导航方式

- 新手入门：从 `01-001 二进制安全概览与学习路线` 开始，沿「前置知识」字段递进学习。
- 按领域学习：进入 [[网络安全知识库主页]] 点击对应领域页。
- 搜索：在 Tolaria 中直接全文检索工具名、CVE 编号或主题词。
