# 02-001 物联网安全概览与攻击面模型

## 基础信息
- 难度：入门
- 前置知识：无
- 对应语言等级：精通级（C/汇编/Python）

## 核心原理

物联网（IoT）设备与通用计算机的最大差异在于**资源受限、生命周期长、更新困难**。一个典型智能设备的构成包括：传感器/执行器、MCU 或嵌入式 SoC（如 ARM Cortex 系列）、运行固件的 Flash、对外通信的无线协议栈（Wi-Fi/BLE/Zigbee/NFC/蜂窝），以及上下行的云平台与移动 App。攻击面因此跨越物理层、链路层、应用层与云端四个平面；一条完整攻击链往往从「拿到固件」开始，到「控制设备」结束。

权威的攻击面建模框架是 MITRE 的 [ASTRID](https://attacks.mitre.org/iot/)（攻击推理数据库）以及 OWASP IoT Top 10（2024/2025 版）。ASTRID 按「组件（Physical/Logical/Cloud）」×「资产（数据/代码/硬件/配置）」×「过程（读取/执行/修改）」三维度枚举攻击意图，把散落的漏洞归拢为可复用的攻击模式。

## 技术要点

- **固件（Firmware）**：设备灵魂，存储于 SPI NOR/NAND Flash 或 eMMC。固件常为压缩/加密的 SquashFS、JFFS2、CramFS 或裸 bin 镜像，逆向需 `binwalk` 识别与提取。
- **调试接口**：UART（通用异步收发）、JTAG、SWD。UART 常暴露 root shell；JTAG/SWD 可读内存、绕过安全启动。
- **无线协议**：Wi-Fi（WPA2/WPA3）、BLE（GATT 服务、配对绑定）、Zigbee/Thread（IEEE 802.15.4）、射频（Sub-GHz，如 433MHz 遥控）。射频攻击需 SDR（HackRF、RTL-SDR）。
- **安全启动与信任根**：Secure Boot / TrustZone / TPM、安全固件更新（签名校验与版本防回滚）。护不住信任根则所有高层防护都可被绕过。
- **云与 App**：设备弱默认口令、云 API 越权、App 硬编码密钥、OTA 更新通道劫持。

## 实践示例

环境：Ubuntu 22.04 LTS、binwalk 2.3.x、qemu-user-static 14.0。

拿到一个路由器固件后的标准第一步——结构与文件系统识别：

```bash
binwalk firmware.bin                 # 扫描嵌入文件
binwalk -Me firmware.bin             # 递归提取到 _firmware.bin.extracted/
file _firmware.bin.extracted/rootfs  # 判断是否为 SquashFS
sudo unsquashfs rootfs               # 解包文件系统
ls extracted-rootfs/etc/passwd       # 查看默认账号
```

提取出的 rootfs 可用 qemu-user 模拟执行其中的程序（如提取 busybox 或 Web 服务程序）：

```bash
qemu-arm-static extracted-rootfs/bin/busybox --list | head
```

## 常见问题与误区

- 误区一：把「拿到固件」等同于「能逆向」。固件可能加密或有启动校验头，解密路径（如从 UART 或 JTAG 安全取件）常比静态破解更现实。
- 误区二：只测 Web 后台而忽略射频与物理链路。多数消费级设备攻击面在无线协议与调试接口，而不是 HTTP 服务。
- 误区三：认为设备「离线就安全」。本地提取、固件签名绕过与蓝牙/射频攻击都不依赖外网；离线设备同样可被物理接触者控制。
